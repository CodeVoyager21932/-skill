# oh-my-FolkStoryPhoto Web

把选中的题做成一组**一眼进入、一直看得懂、图数不漂、成图像真的**的连续图片。

本 Skill 是严格生产流水线。不要把它执行成自由创作会话。

## 0. 四条不可违反的总规则

1. **阶段不可跳。** 故事和正式分镜是阻塞式确认门；分镜确认后必须先真实完成固定资产，再生成正式 Frame。
2. **N 一旦确认就冻结。** 正式图只能填充 `F01...FN`；返修覆盖原 Frame ID，不新增图号、不跳号。
3. **分镜负责观看设计，生图负责现实记录。** Storyboard 可以决定哪里慢/快、第一/第三视角、谁先看到、露多少；正式 Prompt 必须把这些意图翻译成现实站位、动作、遮挡和拍摄结果，不能继续用导演语言主导成图。
4. **真实先于漂亮。** 人物、场景、神祇、鬼怪、虚构生物和幻想空间都必须像真实世界中可被观察/拍摄的对象或现象；禁止默认电影感、插画感、游戏概念设计、油亮磨皮、英雄构图和统一高级调色。

## 1. 严格状态机

只允许按以下顺序推进：

`INTAKE → STORY_DRAFT → WAIT_STORY_APPROVAL → STORY_LOCK → STORYBOARD_DRAFT → WAIT_STORYBOARD_APPROVAL → STORYBOARD_LOCK(N) → ASSET_BUILD → ASSET_LOCK → GENERATE → REVIEW → REPAIR → COMPLETE`

关键执行规则：

- `WAIT_STORY_APPROVAL`：只处理故事；不得提前分镜、资产、生图。
- `WAIT_STORYBOARD_APPROVAL`：只处理正式分镜与随分镜一起展示的**固定资产交接清单**；不得提前资产生图。
- 正式分镜提交时必须同时给出 `FIXED_ASSET_HANDOFF`：只用文字列出 `资产 ID｜名称｜锁什么`，让用户在确认分镜时就知道后续会固定什么；这不是资产图，也不允许提前生图。
- 用户确认分镜后，**下一次允许的图像动作只能是资产生成，不是 F01**；直接沿用已展示的 `FIXED_ASSET_HANDOFF` 作为初始资产队列，不得在交接处把资产需求丢失后重新猜一遍。
- 进入 `ASSET_BUILD` 后，下一步必须是当前资产队列中的具体 `A-*`；队列没清空前禁止正式 Frame。
- `ASSET_LOCK` 后才进入正式 Frame。
- 正式 Frame 从最小未完成 ID 开始，每轮连续生成 **9 张**；最后不足 9 张时生成剩余全部。
- 工具的单轮图片上限只影响批次大小，不允许让模型重新选帧、跳号或询问“想先生成哪 9 张”。
- `INTAKE` 进入正式 Story 前做一次极短的**题目生命力检查**，不新增状态和审批门：第一层异常发生以后，题目本身是否会自然长出下一步；下一步是否有机会带来新的事件、后果、威胁、空间、理解、选择或兑现。若一句话已经把最终最值钱的对象 / 大景说透，后续只剩走近、进入和看细节，或若不额外外挂第二套大机制就无法继续，先停在 `INTAKE`，提出最小 Topic 修正并等用户确认。不要用突然加怪物、幕后组织、实验室、身份反转或额外世界层级给弱题续命。

详细执行见 `references/workflow.md`。

## 2. F01：陌生用户必须先站稳

只要题材自然支持，叙述优先第一人称，但叙述人称与画面视角分开。

F01 的字幕/必要文字必须用最低必要信息交代：

- 我是谁 / 主角是什么身份；
- 为什么今天会在这里，或正在做什么；
- 当前故事从什么现实处境开始。

**题材自然支持时，核心吸引物、异常迹象或故事承诺可以同时进入 F01。** 不要为了背景完整，把真正让人想看的东西机械推迟到 F02–F04。F02–F03 可以继续补普通环境/任务，并让第一处具体偏差、问题或变化更清楚。

第一人称叙述不等于每张第一视角。画面可以来自本人、同行者、路人、监控、工作设备或其他真实可达观察位置。

## 3. 只有三个作品目标

1. **STORY｜事情会继续发生，看完有兑现。** 陌生用户能复述清楚发生了什么，也能说出自己一路主要在等什么；第一层异常之后，故事通过新的事件、后果、威胁、空间、理解、选择或兑现继续生长，不能只反复证明同一个前提，也不能只演示同一机制还能怎么玩。
2. **BOARD｜把图数花在值得看的地方。** 已经懂的地方压缩；观众会想亲眼看清的核心变化、关键证据/结果、进入过程、关键动作、尺度变化和最终兑现可以展开。
3. **IMAGE｜像一段真的拍摄经历。** 图片首先像现实发生的一秒，其次才是视觉表达；整组不做统一精致剧照。

## 4. 故事只写到够，但不能过早结束

进入 `STORY_DRAFT` 后，**先读取 `references/story-development.md`**。先从已锁 Topic / Handoff 提取 `PRESERVE_LIST` 与 `INNOVATION_ANCHOR`，写最自然的 `BASELINE_STORY_SPINE`，再诊断唯一主要弱点。Baseline 已经成立时停止结构创新；只有明确弱点存在时才按 `PRESERVE → REPAIR → RECONSIDER → REBUILD` 局部修复。用户明确要求参考 benchmark 时，可以学习高学习价值作品的成熟 story grammar；不能把原人物、地点、标志物、逐段反转链或结局移植进来。

Production **不欠作品第二个主创新**。Topic 已经有一个具体、好看的核心时，优先把它讲完整、讲清楚、讲到 payoff；不要为了“中后段升级”自动增加第二套世界、幕后组织、身份反转或新机制。反过来，真正更强且理解成本可控的新方向仍然允许胜出，不把“简单”变成硬模板。

正式写故事前，再在内部写一句 `MAIN_VIEWING_PULL`：

> **观众看这篇故事，最主要在等什么？**

它只是写作控制线，不新增状态、不新增用户审批门，也默认不单独输出。若输入来自新版 Topic Handoff，优先读取 `后续观看牵引`；若只有旧字段 `下一层观看问题`，继续兼容，并把它理解为后续观看牵引的一种形式。若 `MAIN_VIEWING_PULL` 只能写成“我想知道这套机制到底怎么运作”，提高警惕但不自动判失败；尽量再确认观众是否还在等待一个会发生的结果、逼近的威胁、打开的世界、具体真相、人物选择或真正兑现。

写故事时：

- 用普通事件句讲清楚，不靠规则百科和世界观解释撑住；
- 可以不知道“为什么会这样”，不能不知道“刚才到底发生了什么”；表层事件事实必须比作者脑内解释更清楚。
- 核心答案、真相或最终兑现可以延迟，但故事经过主要段落时，观众应能感觉自己正在**更接近、更看清、更深入、更受影响、重新理解或更靠近兑现**，不能长时间只增加信息而没有接近感；
- 当观众已经理解并相信核心前提 / 问题，下一段如果只是换载体、地点或证据继续证明同一结论，不自动算升级。优先让 `MAIN_VIEWING_PULL` 获得新价值：持续接近或进入、异常产生后果、人物选择 / 判断改变、对象或关系被看懂更深、空间 / 尺度真正打开、前文被重新理解、核心承诺进一步兑现，或自然出现新的观看问题。持续接近只有在带来题目未提前给出的新价值时才算推进；走得更近、进入内部、看到更完整全景，如果只是把标题里已经说透的对象拍清楚，不足以撑住故事；
- **行动和即时反馈是工具，不是配额。** 观察、调查、等待、跟随、被迫经历都可以成立，只要它们真的推进主观看牵引；不要为了“推进”把故事改成连续测试、冲突、追逐和结果的事件流水线；
- **防机制演示流水线。** 如果连续几个主要段落都能概括成“人物改变一个变量 → 观察同一机制反馈”，同时人物目标、现实处境、威胁、空间、事实理解和选择都没有实质变化，压缩重复测试或让异常真正进入人物处境。测试本身允许存在，只有当测试替代了故事生长时才修；
- **成熟路线不需要主动躲。** 同一威胁持续逼近、旧事件被新证据重启、一路探索进入未知、单线调查抵达具体真相，都可以支撑强故事。判断它们有没有新观看价值，不因为“见过这种 spine”就额外发明第二机制；
- 到故事中后段至少要出现一次**实质升级**：威胁真正逼近、异常造成不可逆后果、世界 / 尺度打开、对象被重新理解、调查抵达具体真相、人物选择产生结果，或核心承诺发生到更高一层。升级不等于反转，也不要求新世界观；同一威胁持续逼近同样可以成立；
- 可以有支线人物、次级异常、误判、世界信息和情绪段落，但它们最好增强、改变、延迟兑现或重新解释主观看牵引，不要每隔几段就换一个新的核心怪事；
- 当人物、地点、时间或叙事层级发生明显切换，尤其一次同时改变两项以上时，前后关系必须能被第一次观看的观众立刻接上；关系不清时补最小桥接事实，不靠观众自己拼。
- 会改变观众对前文基本事实理解的关键反转，必须在同段或紧邻后续落成一个可直接确认的事件或证据；行为、身体结果、物件、空间变化、照片/监控等都可以，不强制文书化。
- 最终回报可以是惊恐、震撼、敬畏、激动、悲凉、温暖、荒诞、胜利、牺牲、尺度兑现、关系变化或确认未知；**不要强制结尾反转，也不要强制巨大动作事件**。但前面主要让观众等待的东西，结尾必须通过具体对象、动作、变化、发现、选择结果或事实确认真正发生到一层。若结尾只能用“拟合 / 同化 / 投射 / 被梦见 / 成为数据 / 被收录”等抽象关系词才能描述，再拿掉这些词，只复述观众实际看到的前后变化；复述不出来就说明 payoff 还没有落地；
- 正式提交前做一次**表层故事测试**：暂时删掉结尾的哲思、主题总结和解释性句子，事件本身仍应完整、值得看到结尾、拥有可感知的 payoff。寓意和余味可以保留，但只能作为额外收益，不能替代发生的事；
- **不要为了好懂把谜底提前讲光。** 可以继续隐藏原因、来源、幕后、世界规则与未来后果；清晰度只保护人物当前行动、事件因果、关键发现和本篇结果。路线可以朴素，终点仍应保留陌生度、危险、奇观或意外；
- 强回报后只为解释完整而存在的尾巴删除。

故事提交前执行一次题目生命力 / 入口 / 首刷清晰 / 机制演示风险 / 中后段实质升级 / 跳转桥接与关键反转落地 / 主观看牵引 / 最终兑现 / 表层故事 / 视觉可行性预检，然后给用户唯一正式故事并停止等待确认。**具体标准必须读取 `references/simple-storyboard.md`。**

## 4.5 故事锁后先固定“现实底盘”和“必要的关键视觉关系”

`STORY_LOCK` 后、正式切分镜前，先做一次极短的内部预生产设计；它与正式分镜一起展示并由同一次分镜确认锁定，**不新增第三个用户审批门**。

### REALITY_BASELINE｜锁现实规则，不锁统一风格

只固定这篇作品在现实世界里如何成立，例如：

- 场景本来如何被生活、工作、通行或维护，哪些功能关系、使用痕迹和固定条件自然存在；
- 实际光源、天气、空间限制和拍摄设备会怎样影响可见度与记录结果；
- 稳定观察、临时发现、移动过程、证据记录等不同处境会自然留下什么不同拍摄结果。

禁止把 Reality Baseline 写成全篇统一的美术母版。它不锁统一色调、统一天气、统一构图或统一摄影品质；世界可以连续，但**摄影结果必须服从具体地点、时间、设备和拍摄处境**。真实感也不等于故意把所有地点做旧、做乱、做暗或把所有照片做坏。

### MECHANISM_LOCK｜只锁“普通连续性不足以保护”的关键视觉关系

只有当核心理解或最终回报依赖某个**可被视觉验证的精确关系**，而普通人物/场景/道具连续性不足以保护它时，才在分镜前写 1–5 条不可漂移规则。优先只考虑真正会影响理解的关系：

- **材质身份**：核心对象已经建立的材料或存在形态，不得无剧情依据改变；
- **物理同源**：A 与 B 确实来自同一件物、同一原件、同一局部或同一对象的前后状态时，来源、边缘、纹样、损伤等必须能被验证；
- **结构映射**：A 与 B 不是同一件物、甚至材质完全不同，但剧情要求它们共享某种几何、拓扑、比例、排列或空间关系时，只锁这层关系，不把两个载体伪造成同一张图的贴图/变体；
- **尺度身份**：同一对象的现实尺度不得为了制造冲击无理由变化；故事明确发生尺寸变化时除外；
- **状态连续**：已经发生的可见变化不得无理由回退，损坏、受伤、湿脏、设备状态等都要接得上。

当 Mechanism Lock 涉及多个对象时，必须先区分执行模式：
- `SOURCE_DERIVATION`：确实物理同源，使用单一母版并从母版直接派生；
- `RELATION_REFERENCE`：只是结构/规律对应，写清“必须保持什么、允许变化什么”，各载体独立建立现实资产，**不得为了省事从一张图片母版派生全部载体**。

大多数故事不需要 Mechanism Lock。人物长相、固定服装、普通道具、场景位置、一般受伤/设备状态等，能用 Asset + Continuity 解决时就不要升级成 Mechanism Lock。只有当**关系本身**漂移会让观众误解“发生了什么”或让核心回报失效时才启用；否则明确 `MECHANISM_LOCK: NONE`。Mechanism Lock 不解释世界观，也不要求故事必须有异常规则，只保护真正需要精确视觉验证的关系。

正式分镜必须把 Reality Baseline 落到具体 Frame 的真实记录条件，也必须把 Mechanism Lock 落到关键帧与固定资产设计里。

## 5. 分镜先分配观看时间，再锁 N

`STORY_LOCK` 后先判断：

- **只需知道**：背景、已理解的说明、无新增观看价值的重复验证，尽量压缩；
- **值得亲眼看清**：第一次核心变化/关键事实、关键证据细节、关键选择或关系变化、行动过程/结果、进入未知、尺度变化与最终兑现，按观看价值展开；
- 路途、等待、进入如果本身正在制造悬念、建立真实空间或让观众明确感觉更接近核心承诺，不机械当过场删除。

图数首先服务 `MAIN_VIEWING_PULL` 的建立、接近、变化和兑现。视觉上很有趣但与主观看牵引脱节的支线异常，不因为“好画”就大量占用 Frame。

再切正式 Frame。每张在 Storyboard 阶段确定：

- 本帧视觉任务；
- 观看立场 / 真实观察位置；
- 关键动作瞬间；
- 揭示程度与必要遮挡；揭示只能控制未知内容露多少，不能连理解当前事件所必需的人、动作、对象、关系或结果一起遮掉；
- 当前现实记录条件 / 成像结果：这张为什么能拍清，或为什么会被挡、拍歪、色温难看、轻微模糊/失焦。

真实可达位置始终优先于漂亮机位。遇到重大人物 / 地点 / 时间 / 叙事层级切换时，先检查现有字幕或画面能否让关系立即站稳；不足时保留最小桥接，不机械增加整段。

切完 Frame 后、锁 N 前再做一次 **`CAPTION_CHAIN_PASS`**：只顺读 `F01...FN` 的字幕，逐对检查人物是否突然出现、地点/时间是否跳了、动作为什么开始、上一帧的状态怎么进入下一帧。图片为了节奏省略了下楼、叫人、走到另一处、把事情告诉某人等普通过程时，若缺少这些事实会让第一次观看产生“怎么突然到这里/这个人怎么突然醒了”的割裂，就把**最小桥接事实**揉进前一帧或后一帧字幕，不因此机械新增 Frame。字幕无需像完整剧情一样逐动作连续；画面已经能自然说明、或普通常识可无歧义推断的过渡不补。若必须靠字幕新发明一个 Story 里没有的动机/因果才能接上，回到 Story 修，不用字幕硬救。

若到分镜阶段才发现主线关系、关键反转或结尾本身需要猜，停止用字幕或加 Frame 硬救，按现有回退规则提出最小 Story 修订并重新确认。完成后一次性决定 `N`。**在等待分镜确认的同一轮，还必须从这版正式分镜提取一个极简 `FIXED_ASSET_HANDOFF`，只列真正需要跨帧稳定的人物、重要场景、关键道具/特殊实体与高风险固定状态。** 若存在 `SOURCE_DERIVATION`，交接母版与必要派生；若存在 `RELATION_REFERENCE`，交接各自独立的现实载体并注明它们共同遵守哪条机制关系，不把其中一个误当另一个的图片母版。不逐帧映射资产、不写 Prompt、不把清单画成资产板。

用户确认后，`F01...FN` 与这份固定资产交接一起进入执行：分镜冻结，资产清单直接成为 `ASSET_BUILD` 的初始队列。

详细见 `references/simple-storyboard.md` 与 `references/output-spec.md`。

## 6. 固定资产：先把“谁、哪里、什么”做真

分镜确认后进入 `ASSET_BUILD`，不能直接讨论或生成 F01–FN。

资产只做人物、重要场景、关键物件/特殊实体的现实身份锚点，不重演剧情。

### 资产执行原则

- 优先直接继承分镜提交时已经展示的 `FIXED_ASSET_HANDOFF`，例如 `A-P01 → A-P02 → A-S01 → A-R01`；不要在用户确认后重新从零推断资产。该清单只是文字队列，不是要生成的总览图。
- 一次只处理一个 Asset ID；当前资产失败就覆盖同一 ID 重做，不前进。
- 禁止人物 + 场景 + 道具混合资产板；禁止 A01–A20 总览；禁止先做总表再裁一格当资产。
- 人物资产首先要像**现实中这个人留下的普通身份参考照片**。同一人物三视图有需要时可以补充，但不能以牺牲真实照片感为代价。
- 场景资产要像真实存在、被生活/工作/使用过的空间，不像概念设计场景。
- 风格化资料图不能直接充当现实身份资产。
- `FIXED_ASSET_HANDOFF` 继续保持极简，它只是队列；真正生成每个 `A-*` 前，必须把该条目编译成**紧凑但足够具体的资产执行 Prompt**。人物要锁辨识身份与固定穿着，场景要锁空间结构/固定物/材料与使用痕迹，关键物件要锁尺度/材料/结构/独特特征。以正向描述为主，只在当前资产存在高概率误生成时追加极短的定向负面约束；不能把“Prompt 简洁”执行成“只写几个名词让模型自由发挥”。

### 不存在对象：先提取设计信息，再建立现实证据

神祇、鬼怪、传说人物、虚构生物、幻想建筑/器物如果只有画像、壁画、插画、游戏设定等资料：

1. 先由模型读取资料，提取少量**识别锚点**：轮廓、比例、服饰/装饰、纹样、色块、肢体结构、关键构件或器物等；
2. 把原图的纸张、笔触、线稿、平涂阴影、雕塑脸、海报构图和艺术风格全部停在资料理解阶段；
3. 正式生成资产时，默认**不再把风格化原图作为图像 reference**，而用提取后的文字锚点重新建立一个现实中可存在、可受光、可遮挡、可被相机记录的人/物/空间；
4. 非实体异常则锁定相机真正能稳定记录到的显现方式，以及它与光、环境、物体的交互。

异常可以违反现实规则，但记录它的现实世界、相机和人物不能一起变成插画。

资产队列逐个实际生成并检查通过后才进入 `ASSET_LOCK`。不要新增资产用户审批门，也不要生成资产汇总大图。

详细见 `references/asset-stage.md` 与 `references/authenticity.md`。

## 7. 正式图：每轮连续 9 张，一帧仍是一张独立图

只有 `ASSET_LOCK` 后才能开始正式图。

- 每轮取**最小的 9 个未完成 Frame ID**，例如 `F01–F09`、`F10–F18`、`F19–F27`；最后不足 9 张时生成剩余帧；
- 一个“9 张批次”是 9 个连续独立 Frame 的生成动作，不是把 9 个镜头拼在一张图里；
- 每个 Frame 仍是一张独立完整 3:4 图片，禁止双联画、九宫格、contact sheet、storyboard page、拼贴或嵌入字幕/UI；
- 不让用户挑任意 9 张，不跳号；
- 如果平台单轮限制迫使本轮停止，记录 `NEXT`，下一次从最小未完成 Frame 直接继续，不重新规划；
- 某帧失败只修同一个 Frame ID，不改变 N。

正式 Prompt 以现实拍摄四件事为主骨架：**这一秒发生什么 → 谁从哪里实际看到/拍到 → 人物/空间/现实化对象真实是什么状态 → 当前条件留下什么成像结果**。Storyboard 的视觉任务、第一/第三视角和揭示程度要被翻译进去，但不要以“导演说明”形式压过现实拍摄逻辑。

四件事是**组织骨架，不是字数上限**。正式生成前做一次 `PROMPT_COVERAGE_GATE`：当前主体身份/状态、关键空间锚点、动作阶段、重要位置关系、上一帧必须继承的状态，以及当前最容易被模型误解的高风险点，是否已经写到足以消除会改变剧情/连续性的主要歧义。若仍存在多种都会改变剧情、连续性或资产身份的合理生成结果，Prompt 过于简单，先补正向细节再生成。不要复制整份资产说明；只抽取本帧真正决定正确性的锚点。负面提示只允许少量、定向、贴合当前高风险错误，正向描述始终占主体。

详细见 `references/image-prompt.md`。

## 8. 反电影 / 反插画门

每张实际成图后直接检查。出现任一情况，同一 ID 重做：

- 人脸像演员、美颜照、雕塑或游戏角色；
- 插画、漫画、油画、概念设计、海报、统一古风美术感；
- 电影调色、轮廓光、无理由浅景深、英雄构图；
- 空间过度干净、像搭景或美术设定；
- 每个线索都恰好无遮挡、像摄影机提前知道剧情重点；
- 危险/运动/低照场景仍和静态白天一样稳定锐利。

合理的模糊、失焦、噪点、直闪、反光、欠曝如果确实由当时条件造成且不遮住本帧必须事实，可以保留。

不要靠继续堆 `photorealistic / cinematic / high quality` 修图；改拍摄事件、人物状态、现实位置、现场光、环境使用痕迹和设备结果。
