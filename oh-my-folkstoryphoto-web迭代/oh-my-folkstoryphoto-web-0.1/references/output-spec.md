# 输出规范与 Frame Manifest

## 1. 故事阶段

只输出：

- 工作标题；
- 叙述者/叙述人称；
- 核心观看欲望；
- 最低必要背景；
- 正式故事。

正式故事输出后必须停止：

> 本阶段到这里。请确认这版正式故事；确认后我再进入正式分镜。

未确认前不输出正式分镜，不生成资产，不生图。

## 2. 分镜阶段

在内部先判断哪些段落展开、哪些压缩；不要在用户表格里增加“快/慢”标签。

### 分镜提交前先展示两份极短预锁

如果当前作品需要，正式分镜表前先给：

```text
REALITY_BASELINE
- <世界如何被真实使用 / 主要真实光源 / 拍摄条件如何随处境变化>
- <不同地点、时间、设备或处境不应被无理由统一成同一种摄影结果>

MECHANISM_LOCK
- <按需写 1-5 条；下面三种写法是可选示意，不要求同时出现>
- M1 <普通关系锁>
- M2 [SOURCE_DERIVATION] <若多个对象确实来自同一物理来源，写清必须同源什么>
- M3 [RELATION_REFERENCE] <若不同对象只共享抽象结构，写清“必须保持什么 / 允许变化什么”>
```

`REALITY_BASELINE` 不是色调、天气、摄影风格套餐；它只锁现实环境的功能、主要真实光源、使用状态和拍摄限制，不锁统一摄影品质。`MECHANISM_LOCK` 也不是世界观百科，更不是所有故事的必填“异常规则”；只有普通 Asset + Continuity 无法可靠保护、且核心理解依赖精确视觉关系时才启用，不需要时写 `MECHANISM_LOCK: NONE`。

这两份预锁与正式分镜、`FIXED_ASSET_HANDOFF` 由同一次分镜确认一起冻结，不增加审批门。

正式分镜使用下面七列；新增的“现实记录条件/成像结果”在分镜阶段就决定拍摄难度与合理瑕疵，不等到生图时随机添加：

| Frame ID | 字幕/必要文字 | 本帧视觉任务 | 视角/观察位置 | 画面与动作瞬间 | 现实记录条件/成像结果 | 连续/揭示/机制关系 |
|---|---|---|---|---|---|---|

其中：

- **本帧视觉任务**：这一张最主要让观众发现、确认、经历或看清什么；
- **视角/观察位置**：不仅写第一/第三视角，还写谁的位置、从哪里看；
- **画面与动作瞬间**：写动作发生到哪一秒；
- **连续/揭示变化**：写上一帧保留什么、本帧新增什么、是否只露一部分/终于看清/展示尺度。

Frame ID 从 `F01` 连续到 `FN`，不跳号。

新增两列约束说明：

- **现实记录条件/成像结果**：在分镜阶段就决定当前处境是否真的会影响清晰度、遮挡、裁切、色温、运动、对焦、反光或曝光；只能来自当前环境和拍摄行为。不受特殊限制时写“普通稳定记录”即可，不设“瑕疵配额”，也不为了“纪实”故意做坏。
- **连续/揭示/机制关系**：除了上一帧状态与揭示变化，若本帧承担核心机制兑现，还要明确必须保持的材质、物理同源 / 结构映射、尺度或状态关系。`RELATION_REFERENCE` 只要求关系可辨认，不要求不同载体共享同一纹理、材质或形成痕迹。

分镜提交前还要检查：不同地点、时间和拍摄处境是否无理由共享同一套美术化灯光、调色、构图和摄影品质；如果是，先回到 Reality Baseline 和各帧拍摄条件重新分配。

### F01 提交门

展示分镜前内部检查：

- 字幕/必要文字明确交代人物身份 + 起因/当前处境；
- 画面支持身份与现实背景；
- 不要求观众靠后文才知道“我是谁、为什么在这里”。

### 分镜提交前再检查

- 图数是否优先给了观众真正想亲眼看清的段落；
- 慢推进是否真的让可见程度、距离、人物意识、动作阶段或空间关系变化；
- 第一/第三视角是否服务观看体验，而不是换花样；
- 观察位置是否现实可达；
- 重要对象、核心变化或最终回报是否被过早完整展示；
- 揭示/遮挡是否误伤了理解当前事件所必需的人、动作、对象、关系或结果；
- 重大人物 / 地点 / 时间 / 叙事层级切换是否已由现有字幕或画面建立最小桥接；
- 是否做过 `CAPTION_CHAIN_PASS`：把字幕单独顺读时，相邻帧的人物加入、下楼/出门/抵达、叫醒/告知、动作触发与知识状态有没有产生不必要的突跳；能用一句最小字幕胶水解决时，不机械新增连接帧；
- 必要连接帧是否被误删；
- 重复验证是否占用了太多 Frame；
- 如果主线关系、关键反转或结尾本身仍需要猜，是否已经返回 Story 修复，而没有靠新增字幕/Frame 硬救。

表后先给 Frame Manifest：

```text
N = 28
FORMAL_FRAMES = F01-F28
```

然后**必须在同一轮继续给出固定资产交接**，不能只说“确认后再做资产”而不说明要固定什么。

固定格式：

```text
FIXED_ASSET_HANDOFF
A-P01｜主角｜身份/年龄/体型/发型/固定衣着
A-P02｜重要配角｜身份/年龄/固定外观
A-S01｜重要场景｜空间结构/固定设备/使用痕迹
A-R01｜核心物件/关系载体｜结构/材料/关键特征；仅 `SOURCE_DERIVATION` 时标为母版
```

只列真正需要跨帧稳定的对象。对神祇、鬼怪、虚构生物或幻想空间，可在“锁什么”里极短注明“仅继承文字识别锚点，现实化重建”，不要把原始风格图当资产。

如果 `MECHANISM_LOCK` 标记为 `SOURCE_DERIVATION`，`FIXED_ASSET_HANDOFF` 必须把对应母版与必要派生资产明确列出来。

如果标记为 `RELATION_REFERENCE`，则列出各自独立的现实载体资产，并在“锁什么”里注明共同遵守哪条 Mechanism Lock；**不要建立虚假的图片母版，也不要把载体 B 当作载体 A 的换材质派生图**。不要等到 ASSET_BUILD 才临时判断关系类型；没有这类关系时不要为了形式强加 A-R 派生资产。

**不要增加逐帧 `Fxx→A-*` 映射，不要写资产 Prompt，不要渲染资产总览图。** 这份 handoff 的目的只是让用户和下一阶段都明确：分镜确认后到底要先固定哪些人物、空间和关键物。

正式分镜 + `FIXED_ASSET_HANDOFF` 输出后必须停止：

> 本阶段到这里。请确认这版 REALITY_BASELINE、MECHANISM_LOCK（如有）、N 张正式分镜及固定资产交接；确认后我按这份资产清单逐个生成固定资产，再进入正式 Frame。

## 3. 分镜锁后

锁定：

- N；
- `F01...FN`；
- 顺序；
- 每个 Frame 的核心可见事实；
- 已确认的观看立场 / 信息先后 / 揭示意图。

后续不得创建新正式 Frame。

不计入 N：A-* 资产图、T-* 测试图、失败候选、同一 Frame 的返修版。

## 4. 资产阶段输出

用户确认分镜后，不再讨论“要先生成哪几张正式图”。进入 `ASSET_BUILD`。

**直接沿用刚刚随分镜展示并被确认的 `FIXED_ASSET_HANDOFF` 作为初始资产队列。** 不要再临时发明一份不同清单。

资产索引仍最多保留：

`资产 ID｜名称｜锁什么`

例如：

```text
A-P01｜主角｜身份/年龄/体型/固定衣着
A-S01｜重要场景｜空间结构/固定设备/使用痕迹
A-R01｜核心物件｜结构/材料/关键特征
```

这个列表只是文字执行队列，禁止渲染成资产总览图，也**不是资产生成 Prompt**。每次处理当前 Asset ID 前，按 `references/asset-stage.md` 把该条目展开成紧凑、正向、细节足够的 `ASSET_EXECUTION_SPEC` 后再生成。

每次处理当前一个 Asset ID。资产通过后进入下一个；全部通过后直接 `ASSET_LOCK`，不新增用户审批。

阶段摘要示例：

```text
STATE: ASSET_BUILD
NEXT_TOOL_ACTION: GENERATE A-P01
FORMAL_FRAME: FORBIDDEN
```

资产完成：

```text
STATE: ASSET_LOCK
NEXT_TOOL_ACTION: GENERATE BATCH F01-F09
```

## 5. 正式图片阶段：每轮连续 9 张

只允许在 `ASSET_LOCK` 后开始。

- 正式图固定竖版 3:4；
- 每个 Frame 都是一张独立完整图片；
- 按最小未完成 Frame 顺序推进；
- 每轮最多/默认生成连续 **9 张**；
- N=28 时依次为：`F01-F09`、`F10-F18`、`F19-F27`、`F28`；
- 不允许让用户任选 9 张；
- 不允许跳号；
- 不允许把 9 张合成九宫格、storyboard、contact sheet 或拼贴；
- 某帧失败只覆盖当前 Frame ID。

每批完成后只需要极短状态：

```text
N=28 | DONE=F01-F09 | NEXT_BATCH=F10-F18
```

如果平台限制导致一批没完成 9 张：

```text
N=28 | DONE=F01-F06 | NEXT=F07
```

下一轮直接从 F07 继续，不重新规划和选择。

## 6. 新增镜头请求

执行中确实需要新镜头时不能自己加：

- 停止；
- 提出最小 storyboard 变更；
- 展示受影响区间与新 N；
- 等用户重新确认；
- 新 Manifest 锁定后继续。
