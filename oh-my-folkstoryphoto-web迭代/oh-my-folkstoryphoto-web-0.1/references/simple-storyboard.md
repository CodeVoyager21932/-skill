# 入口、故事兑现与分镜分配

只解决四件事：一开始能不能马上进入；故事有没有真正兑现；哪里该展开/压缩；每帧应该从哪里看。

## 1. F01：先交代“我是谁 + 为什么在这里”

第一帧面向完全不知道前情的陌生用户。F01 字幕/必要文字至少让人知道：

- 主角是谁 / 什么身份；
- 为什么今天在这里，或正在做什么；
- 故事从什么现实处境开始。

信息只给最低必要量。**题材自然支持时，核心吸引物、异常迹象或故事承诺可以和身份/起因同时进入 F01**，不要为了背景完整机械拖到后面。F02–F03 可以继续补普通环境/任务，并让第一处具体偏差、问题或变化更清楚。

画面支持身份即可，不强行正脸肖像。

## 2. 叙述人称与画面视角分开

叙述控制“谁在说、知道多少”；画面控制“观众借谁的位置看”。

同一组图可以自然出现：

- 主角第一视角；
- 同行者 / 路人 / 同事的近身第三视角；
- 监控、行车记录、工作设备；
- 自拍 / 合影；
- 历史/神话中真实可达的观察位置。

不要为了换镜头而换镜头。每次选择视角先问：

> **这一帧希望观众和角色一起发现，还是希望观众比角色早一步发现？**

再问：

> **要看清的是人物、证据、人与危险的距离，还是世界尺度？**

如果最戏剧化的机位现实里不存在，放弃那个机位。

## 3. 故事先保证“发生了什么”清楚，再保证“看完值”

正式写故事前，在内部用一句话锁定 `MAIN_VIEWING_PULL`：

> **观众看这篇故事，最主要在等什么？**

它不新增审批门，也不要求每一段只讲同一件事；它只是帮助判断支线、发现、行动和慢推进有没有共同服务一个清楚的观看中心。

提交故事前先做 **首刷四问**。按第一次刷到、不能暂停回看的陌生观众判断：

1. 主角现在遇到了什么？
2. 他为什么接下来会做这件事？
3. 他后来实际发现 / 遭遇 / 确认了什么？
4. 最后具体发生了什么？

任何一问只有借助“可能、应该、也许、我猜、其实暗示的是……”才能成立，先修 Story。随后再问：观众是否能用两三句话复述整条主线，并说出自己一路主要在等什么；主要段落是否持续让这件事更近、更深、更危险、更具体、被重新理解或更接近兑现。

允许保留原因、来源、幕后、世界规则、未来后果或更深真相未知；这些未知不能替代当前事件事实。最终答案可以延迟，但不能长时间只增加资料、线索或怪象而没有接近感。

核心前提/问题已经被观众理解并相信后，下一段如果只是换载体、证据或地点再次证明同一结论，不自动算升级。保留它至少要做到一项：

- 让人物更接近、进入、使用或真正遭遇核心对象/空间；
- 造成新后果；
- 改变人物选择；
- 改变对前文的理解；
- 让对象、关系、空间或尺度第一次被看清到新的层面；
- 把事情推进到此前没有真正发生的新层面；
- 让前面的核心承诺进一步兑现；
- 或自然产生一个新的观看问题。

**不要求每段都“行动 → 即时反馈”，也不要求强制换问题。** 调查、等待、观察、跟随、进入过程本身都可以成立，只要观看价值真的推进。

### 2.9 先保住题眼，再判断 Story 是否真的需要“再创新”

正式 Story 的 Baseline / benchmark 借力与修复顺序读取 `story-development.md`。这里继续遵守一个边界：**已经成立的入口、人物动机、核心异常与 `INNOVATION_ANCHOR` 先保留；中段或 payoff 有具体问题时只修该弱层。**

熟悉 story spine 本身不构成缺陷。同一威胁持续逼近、单线调查、一路探索、旧事件被新证据重启，只要每一段都让 MAIN_VIEWING_PULL 更近、更危险、更具体或真正兑现，就可以保持简单。只有局部修复仍救不了核心发动机时才回上游重构。

### 3.0 先确认题目会长，再展开故事

正式展开 Story 前做两次很短的内部检查：

**题目余量**：

> **一句话题目 / Handoff 是否已经把最终最值钱的对象、空间或结果基本说完？如果观众现在就看到一张足够清楚的确认图，后面还剩什么只有连续故事才能得到？**

若答案主要是“怎么走到那里、怎么进去、再看更多细节、终于看到全景”，先回题目层做最小修正。一个题仍可保持非常简单，只要最终具体发现尚未被前提提前说透，或已公开对象本身会继续产生行为、后果、威胁、选择、关系、功能或尺度重定义。

**事件生命力**：

> **第一层异常发生以后，事情会自然推到哪里？下一步会不会带来一个新的事件价值？**

如果不额外添加第二套大机制就走不下去，先停在 `INTAKE`。不要靠突然增加怪物、幕后组织、实验室、身份反转或额外世界层级续命。

### 3.0.1 防“机制演示”替代故事

测试、调查和验证都允许存在，但连续几个主要段落如果都只是“改一个变量 → 看同一机制反馈”，同时人物目标、处境、危险、空间和事实理解没有变化，说明故事正在变成规则演示。压缩重复测试，或让异常真正造成后果、逼出选择、打开空间、改变理解、靠近人物或抵达具体真相。

到中后段至少应出现一次实质升级。它可以是威胁逼近、不可逆后果、世界 / 尺度打开、身份 / 性质被重新理解、调查抵达真相、人物选择产生结果或核心兑现。**不强制反转，也不强制新问题。**

### 3.0.2 CAPTION_CHAIN_PASS｜字幕负责补“被图片省略但不能让观众猜”的连接

图片序列不需要像视频一样把每一步都拍出来；字幕也不需要把正式 Story 原样切成 25 段。字幕额外承担一项轻量职责：**当 Frame 为了节奏省略了普通过程，而省略后会让相邻两张产生人物/地点/动作/知识状态的突跳时，用最小事实把它们接起来。**

锁 N 前把 `F01...FN` 的字幕单独顺读一遍，逐对检查：

- **人物 presence**：上一帧只有 A，下一帧 B 已经参与，B 是怎么加入的？若画面不能自然说明，用一句“我把他叫了下来 / 他听见动静也下来了”这一类事实接住；
- **空间/时间**：人物从床上到厨房、从村口到后山、从深夜到天亮，现有时间词、画面或常识能否无歧义接上；
- **动作触发**：上一帧刚发现 X，下一帧为什么突然去做 Y；若 Y 需要一个已发生的决定/刺激才合理，把那个最小触发写进字幕；
- **知识状态**：下一帧某人已经知道上一帧的发现，是否需要说明“我们把这事告诉了他 / 他看见后……”；
- **状态变化**：醒着/睡着、门开/关、物件拿起/放下等，若画面没有承担变化且观众会困惑，补最短连接。

桥接优先揉进承载主要事件的字幕，不单独制造“我下楼了 / 我去叫人了”这种低价值 Frame。例如“屋顶一直没停，我也睡不着，索性下楼喝水”可以同时完成过渡和进入下一事件。

不要过度补：普通动作能从图片直接看懂、时间词已经说明、或省略不影响理解时保持简洁；不要每句都写“然后 / 于是 / 接着”。如果一个跳转必须补一大段因果才能成立，说明 Story 本身缺桥，回 Story 修。

### 3.1 重大切换必须有最小桥接

人物、地点、时间或叙事层级发生明显切换时，问：

> **第一次看的观众能不能立刻知道新段落和上一段是什么关系？**

一次同时改变两项以上时提高警惕。关系不清就补最小桥接事实，例如人物抵达、一个物件被带入、监控/电话把两处接上、必要的时间地点说明等；能用现有事件自然接上就不新增段落。切换本身可以制造惊喜，但“为什么突然看到这里”不能成为额外谜题。

### 3.2 关键反转必须落地

会改变观众对前文基本事实理解的关键反转，在同段或紧邻后续给一个可直接确认的事件或证据。证据可以是人物行为、身体结果、物件、照片/监控、检测、空间变化等；按题材选择最自然的载体，不把“拿文件解释”做成固定模板。

### 3.3 Payoff Payment Test

最终回报不等于反转，也不等于必须发生巨大动作。尺度兑现、人物选择、行动结果、胜利、牺牲、关系变化、敬畏、明确确认未知、终于进入或终于看见都可以。回看最后一段：

> **前面最主要让观众等待的东西，是否通过具体对象、动作、变化、发现、选择结果或事实确认真正发生了？**

如果结尾主要依赖“人物似乎明白了什么”、单一暗示、哲思句、作者解释，或需要重新拼多个伏笔才知道本篇最后发生了什么，先修结尾。若结果依赖一个抽象关系词才能讲清，再拿掉那个词，只描述观众能看到的前后变化；如果这样无法回答“最后具体发生了什么”，payoff 仍未落地。主回报完成以后，可以继续保留原因、来源、幕后、世界观、未来后果和少量余味。

再做一次**表层故事测试**：暂时拿掉结尾的哲思、作者总结、主题解释，单看事件本身仍应完整并拥有 payoff；寓意和余味可以作为第二层奖励，不能承担第一层故事成立的责任。

### 3.4 防止过度纠偏

好懂只要求表层事件与因果站稳，不要求提前解释谜底。可以让观众一直不知道怪物究竟是什么、为什么存在、幕后是谁、世界还有多大。路线可以非常朴素，只要观看抓手、接近过程、危险、尺度或最终发现仍然新鲜。不要为了“丰富”强加身份反转、幕后组织、额外世界层级或支线。

## 4. 切 Frame 前先判断：这里只需“知道”，还是值得“看”

不要按文字长度平均切图。

### 只需知道：压缩

常见于：

- 已经理解的背景；
- 只负责换时间/地点的普通说明；
- 机械重复的操作；
- 已经确信后继续证明同一前提或结论。

通常一张代表图甚至一句字幕就够，但不要机械删除必要连接。

### 值得亲眼看：展开

常见于：

- 第一次真正出现核心变化或关键事实；
- 一个证据需要靠近才看清；
- 人物正在一步步进入未知空间；
- 一个动作过程本身制造紧张；
- 尺度 / 空间关系正在被逐步认识；
- 最终回报正在真正发生。

展开不设固定帧数。判断标准只有：**观众会不会想把这个过程亲眼看完。**

图数优先服务 `MAIN_VIEWING_PULL` 的建立、接近、变化与兑现。一个支线怪象即使单张视觉很强，如果没有增强、改变或重新解释主观看牵引，也不要持续抢占 Frame。

路途、等待、进门、下楼本身如果正在回答“到底会被带到哪里 / 里面有什么 / 我是不是越来越接近前面承诺的东西”，它们不是普通过场，可以展开。

## 5. 慢推进允许同一个事实连续几帧，但观看体验必须变化

同一个核心事件/事实可以连续出现，不要求每张都引入新机制。只要至少一项真的变化：

- 可见程度：刚察觉 → 更清楚 → 看清；
- 距离：远处 → 接近 → 贴近；
- 人物意识：观众先看到 → 人物终于发现；
- 动作阶段：准备 → 执行 → 结果；
- 空间关系：局部 → 关系明确 → 尺度成立。

如果连续 2–3 张在可见程度、距离、人物意识、动作阶段、位置/状态上都没变化，考虑合并。

## 6. 每个正式 Frame 在 Storyboard 层先定四件事

1. **本帧视觉任务**：这一张最主要让观众发现、确认、经历或看清什么；
2. **观看立场 / 真实观察位置**：谁的位置，从哪里看，距离大概如何；
3. **关键动作瞬间**：卡在动作发生到哪一步，不写抽象“逃跑 / 调查 / 观察”；
4. **揭示程度**：什么必须清楚，什么只能露一部分，是否需要真实前景遮挡。只允许隐藏未知内容；如果遮挡会让观众连当前是谁、做了什么、对象是谁、关键关系或结果是什么都无法确认，先改揭示设计。

一张图尽量只有一个主要视觉任务。

注意：这四项是 **Storyboard 的设计信息**。正式生图时必须翻译成现实站位、动作、遮挡和可见事实，不能原样堆成导演 Prompt。

## 6.5 真实拍摄条件也要在 Storyboard 阶段设计

不要先切出一组完美镜头，再到生图时临时撒“噪点、模糊、纪实感”。对每个正式 Frame，在现有四项之外再确定一句**现实记录条件 / 成像结果**：当前处境会不会实际影响清晰度、遮挡、构图稳定度、曝光、反光或对焦。

这一列不是“瑕疵设计栏”。如果没有特殊拍摄限制，直接写“普通稳定记录”即可；不要为了填满字段主动制造缺陷。

按当时处境选择记录状态，不给题材套固定“纪实滤镜”：

- **稳定观察**：拍摄者有时间站稳，可以正常清楚，甚至可以自然好看；
- **临时发现**：来不及准备，可能构图不完整、被现实前景遮住一部分；
- **移动过程**：人物或摄影者正在移动，允许裁切、轻微运动模糊或焦点滞后；
- **证据记录**：目的只是把某个事实看清，可以直白、近、缺少美感；
- **空间确认**：为看清位置、距离或尺度，可以让人物/车辆/建筑构件成为现实比例参照。

具体环境若本来整洁、光线稳定、设备专业，就应符合它自己的条件；不要为了“真实”主动添加破旧、杂乱、昏暗或拍摄缺陷。

**不设瑕疵配额。** 不能规定“每 9 张必须 3 张糊、2 张歪”。缺陷只能来自实际拍摄条件。

### 需要精确关系验证的 Frame 再多问一件事

只有当本帧的核心理解依赖两个或多个对象之间的精确关系，而且普通连续性不足以保护它时，Storyboard 才额外明确：

> 这一张需要把哪一组关系看清到什么程度？

不能只让相关对象同时出现在画面里。如果核心回报依赖“观众能确认它们确实同源、匹配、互补或发生了同一状态变化”，就要设计到共同特征足够可验证；如果当前机位看不清，应改用更合适的证据帧，而不是靠字幕宣布关系成立。普通人物/服装/场景/道具连续性不需要因此升级成 Mechanism Lock。

## 7. Frame Existence Test

每张问：

> 删掉这一张，会不会丢掉值得看的事件/证据，让人物或空间瞬移，或把一个本来应该逐步看清的过程直接跳到结果？

有效理由包括：动作、结果、关键证据、判断改变、世界确认、必要过程、时间/天气/空间状态、真实连接，以及慢推进里的有效观看变化。

弱理由：只换角度；再强调“很大/很旧/很神秘”；字幕换了一句但画面、状态、观看体验都没变。

**不要要求每张都高信息、高刺激。** 普通连接图如果让人物路径、重大地点/时间切换和现实因果成立，就有价值。若缺失连接会让观众必须自己猜“为什么突然到这里/换成这个人”，保留最小桥接。

## 8. N 只决定一次

完成展开/压缩、观看立场和 Frame Existence 检查后，一次性决定 N。

提交用户的正式版必须连续使用 `F01...FN`；用户确认后不再增长。
