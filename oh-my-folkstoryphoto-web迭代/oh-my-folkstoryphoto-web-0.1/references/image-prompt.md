# 正式 Frame 生图：把分镜意图翻译成现实里拍到的一秒

Prompt 是当前 Frame 的临时执行输入，不是独立交付物。

Storyboard 可以有“视觉任务、第一/第三视角、谁先看到、露多少”等设计语言；**正式 Prompt 不要继续围绕这些抽象导演词组织。** 先把它们编译成现实位置、动作、遮挡和可见事实，再生成。

## 1. 正式生成按连续 9 张为一个批次

`ASSET_LOCK` 后，从最小未完成 Frame 开始：

- 第一批：`F01–F09`；
- 第二批：`F10–F18`；
- 之后继续每批 9 张；
- 最后一批不足 9 张时生成剩余全部。

一个批次是**连续执行 9 个独立 Frame 生成动作**。每个 Frame 仍然：

> one Frame ID, one single full-frame image, one moment only

禁止把 9 个 Frame 合成九宫格、contact sheet、storyboard page、拼贴或一张多场景图。

如果平台单轮图片限制使批次停止，记录最小未完成 Frame；下一轮直接从那里继续，不重新选择 Frame，不询问用户挑哪几张。

## 2. 先把 Storyboard 信息“编译”成现实条件

不要把下面这些直接堆进 Prompt：

> 本帧视觉任务：制造紧张；第三视角；观众先知道；揭示程度 30%；主体权重 70%……

改成现实可执行描述：

- **第一视角** → 谁的眼睛/设备，从哪里、什么高度、什么距离看到；
- **第三视角** → 哪个真实在场者站在哪里，主角是否知道镜头；
- **观众先发现** → 关键变化、风险或事实已经在真实画面里，但人物仍在做原来的事、尚未回头；
- **人物一起发现** → 镜头和人物视线同时转向同一个事实；
- **只露一部分** → 具体被门框/椅背/墙/黑暗/距离遮住什么；
- **展示尺度** → 让真实人物/车辆/门等成为比例尺，而不是写“宏大震撼”；
- **关键动作瞬间** → 写身体/手/头已经动作到哪一步。

编译完成后，Prompt 重新回到现实拍摄逻辑。

## 2.5 读取已经锁定的 Reality / Mechanism 信息，不重新设计风格

正式生图前同时读取三样：

1. `REALITY_BASELINE`：只提取当前地点真实存在的功能、使用状态、光源和拍摄限制；**不要把它重写成统一“视觉风格”**；
2. 当前 Frame 在 Storyboard 里已经确定的“现实记录条件 / 成像结果”：只继承由这一秒真实处境造成的清晰度、遮挡、构图稳定度、反光、曝光或运动结果；不要为了真实性额外添加缺陷；
3. `MECHANISM_LOCK` 与对应 `A-*` 母版/派生资产（如有）：凡是核心关系帧，材质身份、尺度身份、来源/映射关系与状态连续优先级高于画面漂亮。

如果某个 Frame 的核心任务是证明两个对象确实同源、匹配或互补，就必须使用已锁的共同母版/结构证据；不要只靠文字写“完全对应”后让模型重新发明两端。

这些信息只用于把现实条件写具体。最终 Prompt 仍保持下面四项骨架，不增加摄影术语清单。

## 3. 正式 Prompt 用四件事组织，不把“短”误成“信息少”

### ① 这一秒真实发生什么

写人物/对象正在做什么、动作到哪一步、核心可见事实是什么。

不要写抽象：

> “主角正在逃跑。”

更好：

> “主角已经向门外迈出一步，左手仍抓着同伴，头刚回过去看身后。”

### ② 谁从哪里实际看到 / 拍到

写：

- 谁或什么设备记录；
- 为什么这秒会留下图；
- 真实站位、距离、高度；
- 门框、座椅、玻璃、同行者、黑暗等自然遮挡；
- 人物是否知道镜头。

摄影机不能因为剧情需要获得不存在的位置。

### ③ 人、地方、关键对象在现实里是什么状态

只写当前必须继承的少量锚点：

- 人物身份、年龄、固定外观/衣着；
- 地方按真实功能存在，带使用和磨损；
- 必要的已现实化异常实体/幻想结构；
- 与上一 Frame 必须连续的状态。

不要复制整份资产说明，但要把**当前 Frame 一旦省略就会导致身份、空间、状态或剧情关系漂移的锚点**重新写进 Prompt。使用 reference image 不等于文字锚点可以全部省略。

风格化原始资料图不能重新混进正式 Prompt；正式图优先使用已经通过的现实 `A-*` 资产 + 必要上一正式 Frame。

### ④ 当前条件自然留下什么成像结果

只有场景真的会造成时才写：

- 运动模糊；
- 失焦；
- 噪点；
- 直闪前亮后暗；
- 玻璃反光；
- 欠曝/过曝；
- 雨滴、雾气、灰尘；
- 旧设备压缩。

正常稳定拍摄可以正常清楚。不要每张机械撒颗粒和缺陷。

### 3.5 PROMPT_COVERAGE_GATE｜生成前先消除高影响歧义

四项骨架写完后，不按字数判断 Prompt 是否“够”。只检查当前 Frame 的高影响歧义有没有被消除：

1. **主体**：必须出现谁/什么；人物至少有能和固定资产对应的少量身份锚点，异常对象的材料/形态不能留给模型重猜；
2. **动作**：动作进行到哪一步，手里/嘴里/脚下正在接触什么，结果是否已经发生；
3. **空间**：当前在哪个具体空间，主体和门、墙、灶台、走廊、车辆、核心物件等关键锚点的相对位置是否会影响剧情理解；
4. **连续状态**：上一帧已经成立的缺失、破损、湿泥、门窗、衣着、手持物、人物位置等，本帧必须继承哪些；
5. **揭示关系**：哪些必须清楚看见，哪些仍被真实遮挡；若某个“同一/对应/缺失/大小关系”是本帧任务，要写到模型不能随意改成另一种关系；
6. **拍摄条件**：真实光源、观察位置和当前运动/遮挡只写实际影响成像的部分。

判断口诀：**如果删掉某个没写的细节，会让模型有两三种都“合理”但会改变剧情、连续性或资产身份的画法，那条 Prompt 仍然太松。** 先补最短的正向限定，再生成。

### 3.6 定向负面约束｜只挡当前最可能的错

正向描述是主体。只有存在明确高风险误生成时，在段尾加一个很短的 guard，通常 1–3 个点即可，例如：

> `黑色剪纸狗始终是贴墙的薄平面纸片，不生成真实立体黑狗；单张完整照片，不做拼贴。`

不要给每张图复制一长串通用 negative prompt；通用反电影/反插画要求仍由本 Skill 总规则承担。

## 4. 人脸与人物

人物资产只继承身份，不继承资产照片的灯光、姿势、景深和完成度。

脸足够近且设备允许时，可自然出现毛孔、年龄相符的细纹/皱纹、肤色不均、眼周纹理、油脂/干燥、胡渣/碎发、汗、雨、灰尘等。

动作、夜间、遮挡、远距离时允许脸不清楚。不要为了连续性把每张都改成正脸肖像。

## 5. 环境与现场光

只描述真实光源：窗光、顶灯、路灯、车灯、手电、屏幕、闪光灯、火、阴天、雪地反光等。

允许空间里存在与剧情无关但功能合理的线缆、工具、袋子、家具、污迹、磨损、修补和堆放。

让环境实际影响拍摄：窄会遮挡、雨会反光/沾镜、手电只照局部、旧灯色温难看、玻璃会反射。

不要为了“让观众看懂”把人物、证据、关键对象和环境全部摆在最佳位置。

不要使用：`cinematic / film still / dramatic lighting / moody lighting / editorial portrait / award-winning photography / perfect composition / beautiful bokeh / glossy / polished / concept art / illustration / game character design`。

## 6. 紧凑，但要达到执行所需的信息密度

最终 Prompt 保持一个紧凑段落，围绕：

> 现实事件 + 主体/关键对象锚点 + 真实观察位置 + 关键空间关系 + 必须继承的连续状态 + 当前可见程度/遮挡 + 现场成像结果 + 必要时一个短 risk guard

不设固定字数，也不追求把 Prompt 写长。停止条件是：**会影响这一帧正确性的主要歧义已经被消除，剩余自由度只属于无关紧要的自然细节。**

不要拆成摄影教程，不堆焦距、光圈、ISO、色彩心理、电影参考和长 negative list；也不要用“真实、纪实、高质量”几个抽象词代替具体主体、结构和状态描述。

## 7. 生成后只看实际图

先问：

> 这像当时的人留下的一张照片，还是像模型为观众设计的一张视觉作品？

以下情况当前 Frame 直接失败：

- 人脸像演员、美颜、雕塑或角色设定；
- 漫画、插画、油画、游戏概念图、统一古风美术感；
- 场景经过明显美术指导、统一调色、专门打光；
- 匆忙/黑暗/运动场景仍异常稳定、锐利、漂亮；
- 为了看清线索获得不可能的最佳机位；
- 一张图里出现多个 Frame / 多格 / 前后对比。

重做时改现实事件、拍摄位置、人物状态、现场光、遮挡或成像结果；不要只继续加 `realistic / photorealistic / high quality`。
