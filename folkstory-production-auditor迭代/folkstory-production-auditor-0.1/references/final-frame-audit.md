# 最终图片逐帧审查

最终图片审查优先级最高。不要只说“整体不错”。

## 1. 准备输入

尽可能使用：

- 已锁 Story；
- Storyboard / N / Frame IDs；
- Reality Baseline；
- Mechanism Lock（若有）；
- Fixed Asset Handoff 与通过的资产图；
- 资产生成 Prompt / 正式 Frame Prompt（若用户提供，可用于区分 `PROMPT_SPEC` 与 `GENERATION`）；
- 最终 F01...FN 图片。

缺少某项时，明确限制：例如没有 Storyboard，只能审查内部逻辑/连续性/真实性，不能断言“是否符合原分镜”。

## 2. Frame Inventory

先列预期 `F01...FN`，再确认实际产物：

- 缺失；
- 重复；
- 顺序错；
- 同一 Frame 多候选；
- 覆盖候选被误计为新 Frame；
- N 被偷偷增加；
- 正式图是否独立单图。

如果用户提供的是为了审查而拼的 contact sheet，只把它当查看方式，不等同于 Production 违规。

## 3. Frame Contract

对每帧内部建立六项合同：

`WHO/WHAT | WHERE | ACTION | STATE | RELATION/REVEAL | CAPTURE`

### WHO/WHAT
必须出现的主体、关键物件、证据或环境对象。

### WHERE
地点以及人与物的空间位置关系。

### ACTION
必须是 Storyboard 指定的动作瞬间；特别检查动作对象、手里拿的是什么、触碰的是哪里、人物是否已经完成动作。

### STATE
进入本帧时已经成立的状态，包括：破损、缺失、受伤、湿脏、设备开关、衣着、门窗状态等。

### RELATION/REVEAL
对应关系、尺度、距离、遮挡、谁先看到、只露多少、必须严丝合缝/只需结构相似等。

### CAPTURE
摄影者/设备在哪里，以及当前图像清晰度、反光、运动、曝光是否符合该处境。

## 4. 判定顺序

每帧按下面顺序查，不要先看美不美：

1. **剧情事实正确吗？**
2. **完成本帧唯一视觉任务了吗？**
3. **与上一帧/下一帧的状态接得上吗？**
4. **与固定资产、Mechanism Lock 接得上吗？**
5. **拍摄位置和物理世界合理吗？**
6. **如果图片偏差明显，执行 Prompt 本身是否已经把关键主体、空间、动作、状态与关系写够？** 若 Prompt 漏了关键锚点，优先归 `PROMPT_SPEC`；Prompt 足够而图片仍违背，归 `GENERATION`；
7. **有没有明显 AI 痕迹？**
8. 最后才看 P2 级构图/美感。

## 5. 常见 P0 模式

### 核心事实看不见
Storyboard 本帧唯一任务是看清某个缺失/证据/结果，实际图片把它遮住、画错或根本没出现。

### 动作对象错误
要求抓门框，实际抓画面；要求拿纸片，实际变成实体物；要求看窗外，人物却看镜头。

### 关系错误
应该同形、同源、同位置或明确对应，但实际只是两个“差不多”的东西；或者本来只要求结构相似，却被生成为复制贴图。

### 材质/尺度/身份漂移
同一核心物件从纸变毛发、从小件变巨幅板、从固定设备变另一种设备，且剧情没有解释。

### 状态回退
上一帧已经缺失/损坏/打开/受伤，下一帧无理由恢复。

### 角色/场景换身份
不是小发型差异，而是已经不能合理视为同一人、同一空间或同一道具。

### 流水线错误
漏帧、重复 Frame ID、顺序错、覆盖候选被当新帧、N 不一致。

## 6. 连续性矩阵

跨帧重点追踪四类：

- **Identity**：人物/场景/道具是谁；
- **State**：当前已经发生了什么改变；
- **Space**：人物和物体在哪里、怎么移动过去；
- **Mechanism**：核心关系、材质、尺度、来源或结构映射是否保持。

不要把连续性缩成“脸长得像不像”。

## 7. 真实性

### 世界合理性

- 场景是否像真的被人使用；
- 服装/设备/建筑是否有实际功能；
- 天气和环境真的影响人和物。

### 拍摄合理性

- 摄影者能否站在这里；
- 是否有合理记录动机；
- 光源方向与强弱是否说得通；
- 运动时是否仍无理由像棚拍；
- 是否每张都把主体摆在最佳位置。

### 整组反美术统一

当不同时间、地点、设备、处境却反复出现同一种：

- 漂亮侧光；
- 高级统一调色；
- 完美中心构图；
- 同样浅景深；
- 同样锐利无噪点；

把它视为系统性 P1，严重到违背硬性写实要求时可升 P0。

## 8. AI 痕迹

只抓可见且有意义的：

- 手脚融合/数量错误；
- 人物重复克隆；
- 道具结构不可使用；
- 建筑几何融化；
- 文字必须可读却乱码；
- 镜面/玻璃/影子出现重大矛盾；
- 物体穿插、悬浮、纹理复制明显；
- 局部突然变成另一种材质或生物结构。

## 9. 全序列再审一次

逐帧后必须做 sequence pass：

- 有没有某种错误从中段开始持续扩散；
- 是否同一结论被重复太多帧；
- 是否漏掉关键过程导致跳跃；
- 最终 payoff 是否在图片里真正看懂；
- 后半段是否为了规模感改写了早期建立的规则；
- 有没有整组摄影风格越来越像电影/插画；
- 返修候选有没有造成 Frame ID 重复。

## 10. Repair Queue

Repair 只按 `P0 → P1 → P2` 排序，并标：

`Frame ID | severity | root cause | required fact | actual problem | minimal repair`

如果图片错、Storyboard 对，先看执行 Prompt：

- Prompt 漏掉会决定正确性的身份/空间/动作/连续状态/关系锚点：先修 `PROMPT_SPEC`，再覆盖同一 Frame ID；
- Prompt 已足够具体，图片仍不执行：按 `GENERATION` 覆盖同一 Frame ID。

如果 Storyboard 本身错：先停在设计层修，不要靠重写 Prompt 或重新抽卡赌图。
