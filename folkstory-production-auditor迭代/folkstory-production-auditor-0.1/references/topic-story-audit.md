# 选题与故事审查

## 1. TOPIC_AUDIT

只审查题目现在有没有进入 Production 的价值，不提前替它写完整剧情。

### 1.0 完整候选披露 / Choice Preservation

当输入里有多个候选时，先建立 `CANDIDATE_REGISTER`，保证每个候选都有稳定 ID（如 `T01...TN`）并被审查。

硬规则：

- `输入 N 个 -> 输出覆盖 N 个`；不能因为内部筛选而少展示；
- 如果 Auditor 自己为了比较提出候选，凡参与过排序 / 淘汰的也必须列出；
- 可以标 `推荐 / 可做但有风险 / 不推荐`，可以给 Top picks，但这只是意见，不替用户删除候选；
- 若候选很多，先用一行一项的紧凑表覆盖全部，再对推荐项做更深分析；
- Auditor 默认不生成隐藏候选池；只有用户明确要求补候选 / 发散时才生成新候选。

### 1.0A CREATIVE_PROVENANCE_AUDIT｜先确认题是怎么被引导出来的

当用户要求原创 / 独具创意，或当前项目已经暴露具体 benchmark / Library 时，先读取 `creative-provenance-audit.md`。

如果能看到真实用户原话与模型后来生成的示例 Prompt，先比较两者：

- 模型新增的是数量、输出阶段、是否写完整 Story 等中性流程要求，可以保留；
- 模型新增了乡村、失踪、祖屋、葬礼、家庭、某种职业、某种怪物等会改变创意分布的方向，记录 `PROMPT_DRIFT = YES`。

再把当前对话 / 项目上下文已经出现过的具体 benchmark 组件视为已暴露参考。对强候选拆成入口债务、人物关系、场景、异常载体、证据方式、推进方式、payoff 家族，检查单篇复制和多篇组件重组。

输出：

`CREATIVE_PROVENANCE_AUDIT: PASS / RISK / FAIL / NOT_ASSESSED`

必要时补：

- `PROMPT_DRIFT: YES / NO / UNKNOWN`
- `CONTEXT_LEAKAGE_RISK: YES / NO / UNKNOWN`
- `COMPOSITE_LEAKAGE_RISK: YES / NO / UNKNOWN`

如果只能看到最终候选、看不到生成过程，相似只能支持 `RISK`，不能凭推断直接写成 `FAIL`。如果过程证据明确显示模型自行加入创意方向约束，或候选核心明显由已暴露组件拼装，可以判 `FAIL`。

来源审查与题目质量分开。`ENTRY_AUDIT = STRONG`、`HIGH_BAR_CONTENDER = YES` 都可以和 provenance `RISK / FAIL` 同时成立。

### 1.1 TITLE_AUDIT：标题先单独过一遍

如果候选同时有“标题”和“一句话题眼”，先只看标题，不能借一句话题眼替标题补信息。

记录：`TITLE_AUDIT: STRONG / OK / REPAIR / N/A`。重点检查：

- 具体进入事实或现实锚点；
- 观众现在为什么需要下一步；
- 是否停在最早的 `FIRST_SUFFICIENT_DEBT_POINT`，没有机械要求一定交代第一异常；
- 是否泄露第一次昂贵 reveal、深层机制或最终结果；
- 是否呈现强烈“设定 pitch”感；
- 精确数字是在承担现实背景 / 证据 / 故事意义，还是只是异常参数。

标题可以公开核心怪物、地点或对象，只要真正的后续价值来自它持续逼近、行动、产生后果、人物选择或世界打开；不强制第一人称。

### 1.2 BLIND ENTRY AUDIT｜冻结入口判断

在读取 Topic 自己的“这题好看在哪”“后续牵引”“最值钱视觉”“核心兑现潜力”之前，只读取**最早已经发生的入口事实**。如果一句话题眼已经混入第二层，先在内部截到第一处真正成立的事件。

暂时遮住：

- 第二层机制与解释；
- Story Debt 的后续版本；
- Strong Seed Deepening；
- Payoff Ceiling；
- 最终奇观 / 世界；
- benchmark 对这个题的评价。

问四件事：

1. 我现在知道发生了什么吗？
2. 我现在为什么需要下一步？
3. 已经欠下哪一件未完成的事？
4. 如果必须说“后面会发现……”才变有趣，真正钩子是不是来晚了？

冻结：

`ENTRY_AUDIT: STRONG / BORDERLINE / WEAK`

并记录：

`LATE_HOOK: YES / NO`

若保留旧 `RAW_PULL` 字段，其判断必须来自同一次 blind pass，不能被后续字段提高。

### 1.3 LATE_HOOK 与 Downstream Laundering

`LATE_HOOK = YES` 的典型情况：第一层只让人觉得奇怪；第二层出现损失、意图、威胁、关系、现实后果或具体事实以后才真正想看。

优先建议最小修复：把**最早真正制造观看债务的具体事件**适当前移，同时保留后续昂贵 reveal。若前移后仍弱，题目入口需要重做。

硬规则：

> 完整 Topic 的 Deepening、Payoff、大尺度奇观和强视觉可以提高整体潜力，不能反向修改已冻结的 `ENTRY_AUDIT`。

因此允许：

`TOPIC = PASS` + `ENTRY_AUDIT = WEAK` + `HIGH_BAR_CONTENDER = NO`

表示这颗种子后面可能有价值，但当前没有足够竞争力让观众进门。

### 1.4 TITLE_ONLY_REPAIR vs ENTRY_AND_TITLE_REPAIR

标题弱时先看冻结的入口：

- `TITLE_ONLY_REPAIR`：入口本身已有明确债务，只是标题泄题、太虚、太长、句法或包装差；只修标题。
- `ENTRY_AND_TITLE_REPAIR`：标题弱，底层入口本身也弱，真正欲望依赖第二层解释；先回 Topic 修入口，再写标题。

不要用标题文案替上游入口补债。

### 1.5 一级问题

1. **第一层是否直接成立**：普通观众不用先学规则，也能知道现在发生了什么，并知道为什么需要下一步。
2. **题目有没有事件生命力**：入口成立以后，题目本身是否自然带出下一步；若必须 Production 临时再发明第二套大机制才能撑长，属于上游风险。
3. **图片是不是核心**：删掉大段解释，最值钱的东西是否仍能被看见；好画不替入口加分。
4. **确认以后还有没有牵引**：核心前提证明 2–3 次后，继续看是否还能获得新的接近、后果、威胁、理解、尺度、选择、具体真相或兑现。
5. **题目还有没有余量**：一句话是否已经把最终最值钱的对象 / 大景说透；剩下的欲望是否仍需要连续故事满足。
6. **有没有兑现潜力**：题目是否天然通向一个值得亲眼看到的结果、变化、真相或尺度。

### 1.6 STORY_DEBT + PAYOFF_CEILING｜高水位比较时启用

当用户明确要求高质量 / 冠军潜力时，再问：

1. `STORY_DEBT`：入口以后，后续是否继续欠着一件观众真想等的事；不要拿后续 Story Debt 反向洗高入口。
2. `PAYOFF_CEILING`：如果做到最好，是否有一个具体对象、事件、事实、选择结果或可见变化值得等到后面；抽象方向词必须落地。

Topic 阶段只验证 ceiling 的存在，不要求它锁成正式结局。

### 1.7 机制好奇不自动判弱

观众想知道“这套规则怎么运作”可以成立。只有当入口本身已经弱、或核心确认以后后续几乎全部只能靠继续演示同一机制，而没有独立事件、后果、威胁、空间、人物选择、事实重分类、具体真相或终点时，才把它视为竞争力风险。

### 1.8 熟悉母型与真正换皮分开判断

探险、返乡、调查、失踪、工作事故、遭遇怪人、寻找秘境等熟悉入口不自动失败。过度追求“从未见过的异常物理规则”如果牺牲了入口债务，同样属于风险。

真正危险的是：

> **熟悉入口 + 熟悉核心异常 + 熟悉推进方式 + 熟悉终点**

同时成立，而且没有一个具体、不可替换的观看价值。

### 1.8A CREATIVE BALANCE｜创新集中，不奖励堆机制

额外问：

- 这个题最有自己身份的 `INNOVATION_FOCUS` 是什么；
- 其他层使用成熟 story grammar 是否已经足够，不必继续加第二主创新；
- baseline 是否本来已经强，却因为“第一答案太普通”被强行拧出隐藏世界、身份反转、时间 / 空间机制；
- 复杂化以后入口、Story Debt、人物动机、payoff 有没有真正变强；
- 是否反过来过度保守：明显更好、更清楚、更能兑现的新方向有没有因为“熟悉结构优先”被不合理压掉。

记录 `OVER_INNOVATION_RISK: YES / NO / UNKNOWN`。路线熟悉不等于风险，复杂也不等于风险；只看新增复杂度有没有真实收益。

如果使用 benchmark，同时按 `benchmark-use.md` 判断 `IMITATION_RISK`。成熟 spine 相同合法；高度具体的人物关系 + 场景 + 异常 + 推进 / payoff 连续映射才提高风险。

### 1.9 POOL_ENTRY_ENGINE_AUDIT｜个体入口不同于整池入口分布

多个候选时，把专名删掉，只回答：

> **观众为什么现在需要下一步？**

如果多数候选都只能压成“无生命对象 / 环境出现不可能物理行为，所以看看后面还会怎样”，标记：

`POOL_ENTRY_RISK: YES`

这和故事发动机去重分开。后续发动机可以不同，入口仍可能高度同质。熟悉的失踪、返乡、寻找、工作、关系、近身威胁、动物目的行为都可以合法出现，不设配额。

### 1.10 POOL_ENGINE_AUDIT｜个体 PASS 不代表候选池 PASS

多个候选时，把专名删掉，分别概括：异常怎么工作、人物 / 事件为什么继续、后面靠什么产生新价值。如果多个最终候选明显共享同一故事发动机，标记 `POOL_ENGINE_RISK`，建议重新发散其中一部分。

### 1.11 POOL_TITLE_AUDIT｜句式与进入方式分开查

把所有标题单独排在一起：

- 检查句法包装与揭示深度；
- 检查是否共同呈现“时间 / 职业 + 精准异常参数”的 pitch 感；
- 检查精准数字是否大量只是机制参数；
- 若底层入口发动机也聚类，问题属于 `POOL_ENTRY_RISK`，不能只靠换句式解决。

标题句法弱但题眼 / 入口成立时只修标题；入口也弱时回 Topic。

## 2. STORY_AUDIT

### A. 首刷可复述性

先要求陌生观众能用 2–3 句话讲清主线，再逐项检查：

1. 主角现在遇到了什么；
2. 为什么他接下来会继续；
3. 后来实际发现 / 遭遇 / 确认了什么；
4. 最后具体发生了什么。

任何一项只有借助“可能、应该、也许、我猜、其实暗示……”才能回答，视为清晰度缺口。原因、来源、幕后、世界规则和未来后果可以继续未知。

### B. 事件推进

标记每个主要段落属于：

- 新事件；
- 新后果；
- 新威胁 / 距离；
- 新判断；
- 新选择；
- 新空间 / 尺度；
- 事实重分类 / 具体真相；
- 重复证明；
- 机制演示。

如果中段大量只是“重复证明”或“机制演示”，这是结构性风险。

同时检查重大人物 / 地点 / 时间 / 叙事层级切换：新段与上一段的关系是否能被第一次观看的观众立即接上。一次同时改变两项以上时提高警惕；缺少桥接时指出最小缺口，不默认增加完整支线。

### C. 主观看牵引是否继续推进

核心事实已经成立后，问：

> **继续看还能获得什么此前没有获得的观看价值？**

有效推进可以继续围绕同一个问题：更接近、真正进入、威胁逼近、产生后果、改变人物判断 / 选择、看清新的结构或用途、打开空间 / 尺度、重新理解前文、抵达具体真相、进一步兑现。

如果只是换证据、换地点或换载体继续证明同一结论，或只是从远到近、从外到内把题目已说透的对象拍完整，判为原地踏步风险。

### D. 防机制演示流水线

测试、调查、实验允许存在。只有连续几个主要段落都能概括成：

> **改变一个变量 → 观察同一规则反馈**

并且人物目标、现实处境、威胁、空间、事实理解和选择长期不变时，才判为机制演示过重。

最小修复优先让异常真正进入人物处境：造成后果、逼出选择、打开空间、改变理解、靠近人物或抵达具体真相。不要为了修复再加一整套新规则。

### E. 中后段实质升级

中后段至少应有一次事情真正升级。有效形式包括：

- 同一威胁真正逼近或落到人物身上；
- 异常造成不可逆后果；
- 世界 / 空间 / 尺度打开；
- 对象身份或性质被重新理解；
- 调查抵达具体真相；
- 人物选择产生明确结果；
- 核心承诺发生到更高一层。

不强制反转、新问题或额外世界观。路线简单不构成缺陷。

### F. 人物不是摄像头支架

检查人物是否会做选择、改变行动、重新判断、承受结果，或与人 / 物 / 空间发生关系变化。题材天然是被动遭遇时，可以主要承受威胁；不要求强人物弧。

### G. 关键反转落地

会改变观众对前文基本事实理解的关键反转，检查同段或紧邻后续是否有一个可直接确认的事件或证据。它可以来自人物行为、身体结果、物件、照片 / 监控、检测、空间变化等；不要强制文书或检测报告。

### H. Payoff Payment Test

结尾至少完成一件：

- 关键行动真正得到结果；
- 最值得看的空间 / 对象 / 关系被亲眼兑现；
- 人物做出有明确后果的选择；
- 核心未知被更深一层具体确认；
- 观众对前文获得新的、清楚且可验证的理解。

再问：

> **前面最主要让观众等待的东西，是否通过具体对象、动作、变化、发现、选择结果或事实确认真正发生了？**

如果结尾主要靠人物似乎明白、单一暗示、哲思句、作者解释，或需要重新拼多个伏笔才知道本篇最后发生了什么，判为 payoff 风险。若只能靠“拟合、同化、投射、被梦见、成为数据、被收录”等抽象关系词描述结果，去掉该词后再看是否能只用可见前后变化讲清；讲不清同样判为 payoff 风险。

主回报完成后，原因、来源、幕后、世界观与未来后果仍可开放。

### I. 防止过度纠偏、Creative Balance 与情绪

只检查故事自然产生的主要感受是否被事件支撑。不要为了后劲硬加悲伤、反转或哲学意义，也不要为了好懂提前解释所有谜底。

再做一次 baseline 反事实：**如果撤掉后半段后来新增的第二机制 / 额外世界 / 身份反转，原故事是否反而更顺、更想看、更容易兑现？** 如果 YES，记录 `OVER_INNOVATION_RISK`，最小修复优先撤掉无收益的新增层，不推翻前面已经成立的核心。

如果 Story 明确参考 benchmark，检查借的是 story grammar / story inertia / payoff function，还是从人物关系、场景、异常、证据、beat chain 到结局都可映射。后者记录 `IMITATION_RISK`；前者本身合法。

路线简单允许成立；复杂机制也允许成立。审查目标是确认它们真的带来观看价值，而不是把所有作品修成同一种结构。

## 3. HIGH_BAR CONTENDER｜不依赖 benchmark 的高标准判断

当用户明确要求“高质量 / 独具创意 / 最有上限 / 最强 / 冠军候选 / 顶档”时，对 TOPIC / STORY 输出：

`HIGH_BAR_CONTENDER: YES / BORDERLINE / NO / NOT_ASSESSED`

这个判断不能因为没有 benchmark 就跳过。它回答的是：**作品自身是否已经具备可信的高档竞争结构。**

### 对 TOPIC 看什么

1. **Entry pull**：读取已经冻结的 `ENTRY_AUDIT / LATE_HOOK`；后续解释、大景、Payoff 不得重新评分；
2. **Story debt**：第一层之后是否欠着一件观众真想等的事；
3. **Second layer**：是否太快接受第一条顺手答案；简单答案本身很强时允许保留；
4. **Concrete next event**：深挖以后有没有一件真正改变人物处境、行动、风险或事实理解的下一事件；
5. **Middle value**：后续能否获得不同性质的观看所得，而非同一异常变大 / 换证据；
6. **Payoff ceiling**：是否存在具体、可见、值得等待的回报上限；
7. **Comprehension cost**：做到这些以后是否仍能首刷理解。

`HIGH_BAR_CONTENDER` 只评价题本身结构，不替来源独立性背书。若 `CREATIVE_PROVENANCE_AUDIT = FAIL`，仍可保留 high-bar 判断，但不得把这颗题作为 Skill 独立原创能力已通过的证据。

特别警惕：把“更大的世界 / 更深的隐藏空间 / 更复杂的机制”当成天然升级。如果去掉扩世界，只剩“这个现象更宏大”，高标准判断应降级。

### 对 STORY 看什么

Topic 的高潜力是否真正落成了事件：中段有没有具体变化，人物 / 处境是否被卷入，payoff 是否真的发生。Topic 可以 `YES`，Story 仍可能降成 `BORDERLINE / NO`。

### 判定含义

- `YES`：即使不借外部对标，也能证明这题 / 故事有可信的高档竞争结构；
- `BORDERLINE`：至少一个关键层级仍普通、抽象、可预判或过度依赖扩世界；
- `NO`：能做，但当前还没有冠军资格证据；
- `NOT_ASSESSED`：用户没有要求高质量 / 冠军判断，或材料不足。

`HIGH_BAR_CONTENDER` 与 `P0 / P1 / P2` 分开。

## 4. BENCHMARK COMPETITIVENESS｜有明确对标时才启用

当用户提供 benchmark 作品集、明确要求按对标中位数判断，或项目本身已经锁定该 benchmark 集时，对 TOPIC / STORY 再做一条平行判断：

`ABOVE_MEDIAN / AROUND_MEDIAN / BELOW_MEDIAN / NOT_ASSESSED`

只比较四个实际问题：

1. **Title entry + Raw pull**：标题在不泄露主要回报的前提下有没有具体进入力；一句话题眼在没有解释帮助时观看欲望相对如何；
2. **Story inertia**：第一层异常以后，事情是否自然长成下一件事；
3. **Unpredictability**：观众是否过早就知道后面只会如何演示或最终长什么样；
4. **Payoff**：是否有一件值得专门等到最后的具体回报。

竞争力判断和 `P0 / P1 / P2` 分开。作品技术上可以 PASS，但竞争力仍可能低于对标中位数；反过来，一个很刺激的创意如果首刷看不懂或结尾没兑现，也不能因为“有脑洞”放过质量问题。

## 5. TOP_TIER_CONTENDER｜用户要求最高档比较时才启用

只有在用户明确要求“和最高档 / 顶档 / 最强对标不相伯仲”，而且 benchmark 足以识别若干高水位样本时，才输出：

`YES / BORDERLINE / NO / NOT_ASSESSED`

不要只拿一个冠军样本当万能模板。优先从不同发动方式里选择高水位参照，例如：简单威胁逼近、探索 / 世界打开、调查 / 事实重分类、人物命运真相、尺度兑现等。比较的是完成强度，不复制表面结构。

### 对 TOPIC 看什么

1. **Entry pull**：冻结的入口吸力和入口债务，有没有资格和高水位样本放在一起比较；
2. **Story debt**：第一层之后是否欠着一件观众真想等的事；
3. **Second-layer quality**：第二层是否只是最顺手、最容易猜到的第一联想；如果第一联想本身已经简单而强，可以保留，复杂度不加分；
4. **Middle value**：题目是否有能力自然长出性质不同的观看所得，而非同一异常持续放大 / 换证据；
5. **Payoff ceiling**：是否存在具体、值得等到最后的回报上限；
6. **Comprehension cost**：做到这些以后，普通观众是否仍能第一次就跟上。

### 对 STORY 看什么

在 Topic 潜力之外，再看这些高水位潜力有没有真正落成事件。一个 Topic 可以 `YES`，正式 Story 仍可能因为中段普通、理解成本升高或 payoff 没落地而降为 `BORDERLINE / NO`。

### 判定含义

- `YES`：有可信的同档竞争潜力 / 实现度；不代表保证传播表现；
- `BORDERLINE`：至少一两个局部已经达到高水位，但第二层、中段、回报或理解成本仍有明显差距；
- `NO`：可以做、甚至可能 `ABOVE_MEDIAN`，但目前没有足够证据证明它和最高档处于同一竞争层；
- `NOT_ASSESSED`：没有明确最高档目标，或 benchmark 信息不足。

`ABOVE_MEDIAN` 与 `TOP_TIER_CONTENDER` 可以同时出现，例如：`ABOVE_MEDIAN + NO`。不要为了给出 `YES` 强行加反转、复杂时间规则、新组织、新世界层级或额外机制。


## 6. BENCHMARK DEPENDENCE AUDIT｜先分模式，再看依赖是否健康

如果同一或高度等价 Prompt 有两轮结果，一轮使用 benchmark、一轮不使用，记录：

`BENCHMARK_DEPENDENCE_AUDIT: PASS / RISK / FAIL`

先按 `benchmark-use.md` 判断：

- `INDEPENDENT_ORIGINALITY_MODE`：benchmark 不该主导第一轮创意出生；
- `BENCHMARK_GUIDED_MODE`：benchmark 本来就允许改善 story spine / 节奏 / payoff，不能因为结构发生变化就判失败。

### 比较五件事

1. **Learning-value use**：实际学习的 benchmark 是否 craft / transferability 足够高；
2. **Grammar gain**：质量提升是否来自入口功能、人物继续理由、story inertia、payoff function 等可迁移能力；
3. **Signature drift**：人物、地点、标志物、怪物、独特异常、可映射反转链与结局是否向对标集中；
4. **Over-innovation response**：为了避免“像对标”，是否反过来不断叠新机制；
5. **Independent high bar**：即使没有 benchmark，高质量门也是否存在。

### 判定

- `PASS`：模式与用户目标一致；GUIDED 模式可明显改变结构，但主要学习 transferable grammar，新作仍有自己的具体身份；
- `RISK`：有真实质量提升，同时出现表面生态聚集、同一 benchmark 影响过深或为了反模仿而复杂化；
- `FAIL`：独立原创任务直接借具体组件，或 guided 任务已经成为可识别换皮 / 逐段映射。

Repair 不简单禁止 benchmark。优先回到：筛学习价值 → 保留成熟 grammar → 移除作品指纹 → 保住当前作品已成立的 `INNOVATION_FOCUS`。
