# 分镜审查

## 1. 先看 Frame Allocation，再看单张构图

问每个段落：

- 观众只需要知道？
- 还是会想亲眼看清？

已懂的背景、说明、重复确认通常压缩；第一次核心变化、重要证据、进入过程、关键动作、尺度兑现、关系改变与最终回报可以展开。

路途/等待/过门/下楼如果本身回答“到底被带到哪里”“里面有什么”，不当普通过场。

## 2. Frame Existence Test

每个 Frame 至少承担一种新观看价值：

- 新事实；
- 新动作阶段；
- 新空间关系；
- 新可见程度；
- 新人物意识/选择；
- 新尺度；
- 必要因果连接；
- 现实路径/等待本身形成悬念或可信度。

两张画面视觉不同，但回答同一个问题、没有任何观看推进，仍可能冗余。

## 3. 慢推进必须有 delta

同一事实可以连续多帧，但必须变化：

- 从看不清到看清；
- 从远到近并获得新结构；
- 角色从不知道到意识到；
- 动作从开始到造成结果；
- 空间关系从未知到明确；
- 局部证据最终连接成整体。

只换角度不算推进。

## 4. F01

F01 的文字/画面组合必须让陌生人知道：

- 核心主体是谁；
- 为什么今天进入这个故事/正在做什么；
- 最低必要现实背景。

不要求人物正面肖像，也不要求第一人称自拍。

## 5. Viewpoint

检查“谁从哪里能看到这张”。

可以使用：本人、同行者、路人、监控、工作设备、无人机等真实可达位置。

警惕：

- 无人能站到的完美机位；
- 摄影机总比人物更早知道关键线索在哪里；
- 为了变化而机械切第一/第三视角；
- 每个危险都被完整无遮挡展示。

## 6. Reveal

第一次异常或威胁不必总是完整展示。检查每一帧是否明确决定：

- 只看到局部；
- 被什么挡住；
- 角色是否已经看到；
- 观众是否先看到；
- 何时终于看清。

过早把核心东西拍成“怪物证件照”会削弱后续；遮挡过头导致当前是谁、做了什么、对象是谁、关键关系或结果无法确认，同样是错误。揭示设计只保护未知内容，不能牺牲表层事件可理解性。

## 7. 现实记录条件

这列不是“瑕疵栏”。

- 稳定观察可清楚；
- 临时发现可能裁切/遮挡；
- 移动过程可能焦点滞后或轻微模糊；
- 证据记录可以直白甚至不好看；
- 专业设备和有准备拍摄可以非常清楚。

只要拍摄结果服从环境和行为即可。不要设置糊图配额。

## 8. 因果过程、微桥接与字幕链

Storyboard 必须在需要时展示过程，不能只展示原因和结果。人物、地点、时间或叙事层级发生重大切换时，也要检查是否有最小桥接让第一次观看的观众立即知道前后关系。

同时做一次 **Caption Chain Audit**：先暂时不看图片构图，把字幕 `F01...FN` 单独顺读，逐对检查人物 presence、空间/时间、动作触发、知识状态和上一帧已经成立的状态。图片序列允许省略普通动作，但如果省略以后观众会问“怎么突然下楼 / 他怎么突然醒了 / 奶奶怎么突然知道 / 为什么突然去阁楼”，字幕应提供最小连接事实。

不要反向要求“所有动作都必须写出来”。能从画面直接看懂、时间词已说明、或省略不产生歧义时不补；一个微桥可以直接揉进本帧主要字幕。若必须增加重要动机/因果才能接上，根因在 Story；若 Story 本身已有该过程，只是切 Frame/字幕时丢失，根因在 `STORYBOARD`。

重点检查：

- 进入/离开空间；
- 拿起/放下/贴上/拆下；
- 开门/阻挡/失效/恢复；
- 关键职业操作；
- 受伤或设备损坏；
- 人物决定改变路线或目标。

如果缺掉中间动作或桥接会让观众误解“怎么发生的 / 为什么突然到这里 / 为什么换成这个人”，这是 P0/P1 候选。若根因来自 Story 本身，回到 Story 修复，不靠新增 Frame 或字幕遮盖上游问题。

## 8.5 执行 Prompt 充分性（有 Prompt 时才审）

如果用户同时给了固定资产 Prompt 或正式 Frame Prompt，检查“紧凑”有没有变成“欠约束”。

资产 Prompt 至少要让高风险身份有可执行锚点：人物的辨识外观/固定穿着，场景的主要空间拓扑/固定物/材料使用痕迹，关键物件的尺度/材料/结构/独特特征。`FIXED_ASSET_HANDOFF` 本身很短是正常的，但它不能被原样当成生成 Prompt。

正式 Frame Prompt 要覆盖当前真正决定正确性的：主体、动作阶段、关键空间关系、必须继承的连续状态、揭示/对应关系和现实拍摄条件。若一个没看过项目的图像模型可以在这些关键点上自由选择多种互相冲突的版本，记录 `PROMPT_SPEC` 风险。

负面提示不以数量取胜。正向限定应占主体，只在当前高风险误生成处使用少量定向 guard；长通用 negative list 不自动算更充分。

## 9. 固定资产交接

审查 `FIXED_ASSET_HANDOFF` 是否覆盖真正高风险跨帧对象：

- 主要/重复人物；
- 反复出现且空间结构重要的场景；
- 核心道具、证据、特殊实体；
- 容易漂移且剧情依赖的固定状态。

不要为了完整把一次性路人、小杂物全部资产化。

如果关系比对象本身更重要，要确保机制要求进入分镜与资产设计；但普通连续性够用时不要强造机制锁。

## 10. Storyboard 判定

- `PASS`：可以锁 N 进入资产阶段；
- `REPAIR`：局部 Frame/交接可修，不需要重写故事；
- `REDESIGN`：帧分配或因果结构大面积错误，需回 Story/Storyboard 上游。
