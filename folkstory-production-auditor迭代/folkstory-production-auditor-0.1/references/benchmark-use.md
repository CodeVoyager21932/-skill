# 对标作品使用边界｜既防过度隔离，也防过度模仿

Auditor 审查 benchmark 时，不再默认“对标只能最后校准”。先判断用户到底是在测试独立原创，还是明确要求参考优秀作品做正式创作。

核心目标：**benchmark 可以提供成熟故事语法和修复经验；作品指纹不能被直接移植。** 同时，benchmark 本身也必须先接受质量 / 创新判断，不能因为数据高就全盘学习。

## 1. 先判断模式

### `INDEPENDENT_ORIGINALITY_MODE`

用户明确测试独立原创、要求不参考现成作品，或 benchmark 只用于最后审查时：

- 第一轮粗种子应尽量独立；
- benchmark 主要用于竞争力、相似度和外部比较；
- 如果 benchmark 明显改变了第一轮题材生态，记录依赖风险。

### `BENCHMARK_GUIDED_MODE`

用户明确要求参考 / 学习 / 对标优秀作品做正式创作时：

- 允许 benchmark 的成熟 `TRANSFERABLE_STORY_GRAMMAR` 进入 Topic / Story；
- 允许它改变 story spine、人物继续理由、中段惯性、节奏和 payoff function；
- 不要求“有 / 无 benchmark 的第一轮分布完全一致”；
- 重点改查：有没有滑向对标的具体表面生态、签名组合和逐段映射。

如果用户没说清模式，根据任务实际目的判断，不把“当前项目曾经读过 benchmark”自动等同于 GUIDED。

## 2. Benchmark 自己先做学习价值审查

内部判断：

- `CRAFT_VALUE = HIGH / MEDIUM / LOW`：故事完成度、入口、事件惯性、清晰度、节奏、payoff；
- `NOVELTY_VALUE = HIGH / MEDIUM / LOW`：它的新鲜点是否真的有效；
- `TRANSFERABILITY = HIGH / MEDIUM / LOW`：经验能否脱离原作表面仍有用；
- `SIGNATURE_RISK = HIGH / MEDIUM / LOW`：借用后是否容易形成换皮。

审查原则：

- Craft 高 + Transferability 高：适合学习；
- Craft 高 + Novelty 一般：学叙事效率，不把普通题材包装当创新；
- Novelty 高 + Craft 一般：可启发，但不应成为完整 spine 范本；
- 两者都低：即使热度高也不建议主动模仿。

表现数据只帮助定位样本，不替代内容判断。

## 3. 三层学习权限

### 可直接学习：`TRANSFERABLE_GRAMMAR`

- 入口功能 / 第一笔观看债；
- 成熟 story spine；
- 人物为什么自然继续；
- story inertia；
- 信息揭示与节奏；
- payoff function；
- 情绪变轨；
- 图片承担证据、距离、尺度、身份、结果的方式。

### 需转换：`TRANSFORM_BEFORE_USE`

- 人物关系类型；
- 场景类别；
- 证据介质；
- 异常载体；
- 开场情境类型；
- 终局类型。

这些可以提示解法，但必须由当前题重新设计。

### 继续隔离：`SIGNATURE_QUARANTINED`

- 原人物 / 专名 / 地点 / 组织；
- 高辨识人物关系 + 场景组合；
- 标志物、怪物、生物、场面；
- 独特机制的具体实现；
- 可逐段映射的推进 / 反转链；
- 原结局与独有表达。

## 4. `BENCHMARK_DEPENDENCE_AUDIT` 的新判法

如果同时有同一 Prompt 的有 / 无 benchmark 两轮结果：

### PASS

- 在 INDEPENDENT 模式，benchmark 主要改变筛选 / 比较；或
- 在 GUIDED 模式，benchmark 明显改善 story grammar / 修复策略，但新题保有自己的具体身份，没有签名漂移。

### RISK

- 结构提升真实，但候选池开始集中到 benchmark 高频具体场景 / 人物关系 / 异常载体；
- 同一篇 benchmark 对新作开头、中段、结局影响过深；
- 为了“像高水位”把一个本来强的简单题加工复杂。

### FAIL

- 多个候选明显成为对标换皮；
- 新作能从入口到 payoff 逐段映射某篇作品；
- 标志性人物 / 地点 / 物件 / 反转链成为核心价值来源；
- 用户要求独立原创，模型却直接借具体 benchmark 组件生题。

不要把“使用同一种成熟 story spine”单独判 FAIL。

## 5. 创作质量与创新价值分开

审查 benchmark 学习时区分：

- **Craft 值得学吗？**
- **它的创新本身值得学吗？**

一个作品可以故事很好但创意很传统，此时应该学它怎么讲，不要求新作复制它的普通题眼。

一个作品也可以脑洞很新但故事执行一般，此时只把创意方式当可能性，不把它当完整结构标准。

因此“高水位样本”也不是每一层都正确。

## 6. 创意平衡审查

在 Topic / Story 中额外检查两个对称风险：

### `OVER_INNOVATION_RISK`

- baseline 已经强，却因为“第二层要更意外”继续叠机制；
- 为了升级不断开新世界 / 身份 / 因果规则；
- 人物现实动机被抽象机制替代；
- 理解成本明显上升，但观看价值没有同步变强；
- 原题一个很好的具体锚点被“聪明化”到失去原味。

### `IMITATION_RISK`

- 原作具体人物关系、场景、异常、证据、推进和 payoff 连续映射；
- 多篇对标的高识别组件被拆件重组；
- 新题真正最好看的部分主要来自 benchmark 指纹，而自己的内容只是换职业 / 年代 / 地名。

两者可以同时存在：一个作品既可能抄了对标框架，又在后半段为了显得原创继续加机制。

## 7. 竞争力校准

中位 / 顶档比较继续看：

- 第一层原始吸力；
- Story Debt；
- 人物为什么继续；
- 中段 story inertia；
- payoff 具体度；
- 图片承载；
- 理解成本；
- 是否拥有一个具体 `INNOVATION_FOCUS`。

不要把“机制多新”作为唯一脑洞指标。熟悉母型完全可能顶档；高概念也完全可能顶档。谁更好看、谁更清楚、谁更值得等到最后，谁优先。

## 8. 标题与表现数据

标题可以学习揭示深度、进入功能、长短与题材匹配，不复制句式。

点赞 / 分享只作为当前作品集里的辅助信号。不要从“某题高赞”直接推出“它的题材 / 反转必须学习”。

## 9. Auditor 的 Repair 建议

发现 benchmark 使用问题时，优先建议：

1. 保留当前作品已经成立的入口 / 核心异常 / 人物动机；
2. 只移除过近的签名元素，或只撤掉无必要的新机制；
3. 重新选择更适配的成熟 grammar；
4. 局部修复仍救不了结构时才 REDESIGN。

> **对标应该让系统更会讲故事，不应该让系统更像某一篇故事。**
