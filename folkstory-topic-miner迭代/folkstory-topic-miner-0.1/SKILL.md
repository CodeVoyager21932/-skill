# Folkstory Topic Miner

先**想出真正值得做的题**，再判断它是否适合连续图片。不要用一组筛选规则反向拼出“各项合格但没生命”的题。

Topic 负责题眼、原始故事欲望、后续观看牵引、视觉机会与兑现潜力；Production 负责正式故事、节奏、分镜、观看视角、真实感和生图。

## 1. 第一轮先让事情发生，再谈去平庸

不要把用户关键词直接拼成“职业 + 场景 + 异常”。关键词是素材和边界，不是故事骨架。

### Creative Provenance Lock：先锁定真实用户约束，再发散

任何开放式原创、演示 Prompt、已存在 benchmark / Library 上下文的任务，发散前先读取 `references/creative-provenance.md`。内部先区分：

- `USER_EXPLICIT`：用户真实提出的创意方向与限制；
- `TASK_REQUIRED`：Skill 为执行流程补出的中性默认；
- `ASSISTANT_INVENTED`：模型为了“更真实 / 更好演示”自行添加的题材、人物、关系、场景或类型限制。

默认只让 `USER_EXPLICIT + TASK_REQUIRED` 进入第一轮种子生成。用户已经给出实质创作请求时，即使同时要求“make up a realistic user prompt”，也不要擅自补入乡村、返乡、失踪、祖屋、葬礼、家庭、深海、探险等会改变创意分布的方向。演示 Prompt 只补必要的流程约束。

当前对话、项目上下文、此前 Library / benchmark 分析里已经出现过的具体作品都视为**已暴露参考**。但必须按 `references/creative-provenance.md` 拆成两层：成熟的 `TRANSFERABLE_STORY_GRAMMAR` 可以在用户明确要求参考对标时学习；原人物、原地点、标志物、独特场面、具体机制实现、可识别推进 / 反转链和原结局进入 `SIGNATURE_QUARANTINED`。不要把“通用故事语法”和“作品指纹”一刀切成同一种污染。

### Benchmark 分级参与：先判断任务模式，再决定它能进入多深

只要用户提供 benchmark、Library、PDF / ZIP 对标库，或要求“参考 / 学习 / 对标这些作品”，先读取 `references/benchmark-isolation.md`。

- 用户明确要测试独立原创、要求不参考作品，或 benchmark 只用于最后审查：进入 `INDEPENDENT_ORIGINALITY_MODE`，先盲创粗种子；
- 用户在当前任务或已明确延续的项目约束中要求参考优秀作品做正式创作：进入 `BENCHMARK_GUIDED_MODE`。先判断对标的 `CRAFT_VALUE / NOVELTY_VALUE / TRANSFERABILITY / SIGNATURE_RISK`，只让高学习价值的成熟 story grammar 参与种子和修复。

`BENCHMARK_GUIDED_MODE` 允许学习：入口功能、Story Debt、人物为什么继续、成熟 story spine、中段 story inertia、节奏、payoff function、情绪变轨与图片承担的叙事职责。

继续禁止直接借：原人物 / 专名 / 地点、标志性物件 / 怪物 / 场面、独特异常实现、可逐段映射的推进链、反转链与原结局。人物关系类型、场景类别、证据介质、异常载体和终局类型只能经过当前题重新设计后使用。

benchmark 本身不因点赞高或“被列为对标”就自动值得模仿：故事完成度高但创新普通时学 craft；脑洞新但故事弱时只当灵感刺激；两者都弱就不主动借。

内部先生成明显多于最终输出的粗种子，通常 12–20 个即可；**不向用户展示这一轮**。第一轮优先问：

> **今天发生了什么，让一个原本正常进行中的人、关系、任务、地点或事情突然不能照旧继续？**

可以从返乡、失踪、等待、寻找、工作、照看、旅行、调查、现实损失、主动威胁、异常目的行为、传说入口或具体发现开始。强对象、奇观地点、怪异关系仍然合法，但不要把“先设计一件违反物理规律的怪现象”当成默认起手式。需要时读取 `references/divergence.md`。

### Blind Entry Gate：先证明观众愿意进门

粗种子出生后、三步事件试跑前，读取 `references/entry-design.md`。对每个有希望的种子先遮住第二层、后续解释、Payoff Ceiling、最终大景和 benchmark 评价，只看最早已经发生的事实。内部冻结：

- `ENTRY_PULL = STRONG / MEDIUM / WEAK`；
- `ENTRY_DEBT = 观众当前具体欠着什么`；
- `LATE_HOOK = YES / NO`。

如果真正让人想看的事情直到第二层才出现，先尝试一次入口重定位，把最早那件真正制造观看债务的具体事件前移，但不要泄露深层机制或结局。重定位后仍弱就降级。**后续 Deepening、Payoff 和大尺度视觉不得反向提高已经冻结的 `ENTRY_PULL`。**

对通过入口门的种子，再内部做一次极短的**三步事件试跑**，只用于判断种子会不会长，不输出、不锁正式剧情：

1. **第一步**：第一件具体异常 / 事件真正发生了什么；
2. **第二步**：人物为什么自然继续、被迫继续，或异常为什么自己继续；
3. **第三步**：继续以后有没有获得新的观看价值，例如新事实、新处境、新后果、新距离、新危险、新理解、新选择或更大的世界；不要求为了“不同”强行换机制。

三步不要求转折，也不要求人物主动测试。追逐越来越近、空间越来越打开、失踪案越来越接近真相、一个东西开始真正影响现实，都可以成立。若试跑很快变成“解释规则 → 测一次 → 再测一次同一规则”，先把它当成机制概念，降低优先级。

**关系创新保留，但不再是每个种子的默认第二步。** 只有当一个种子已经让人想跟下去、但明显陈旧、换皮或缺少自己的锋利处时，再用时间、身份、空间、因果、观察、功能等关系帮助它脱离旧套路。需要时读取 `references/divergence.md`。

### 强种子先判 Baseline，再决定是否深挖

三步试跑通过以后，不要平均深挖所有种子。先挑 2–4 个原始钩子、故事债务或图像机会最强的种子，读取 `references/top-tier-development.md`。

对每个强种子先写最自然的 `BASELINE`，再判断 `BASELINE_ALREADY_STRONG = YES / NO`：

- `YES`：入口、人物继续理由、Story Debt、中段惯性、payoff 潜力和理解成本都已成立，允许**直接停止继续发散**；
- `NO`：先写清唯一主要弱层，再按 `PRESERVE → REPAIR → RECONSIDER → REBUILD` 修。优先保留已经成立的入口、人物关系、核心行为 / 异常和最值钱视觉；局部修复有效就停，只有核心发动机仍然无法成立时才重构。

内部同时写一句 `INNOVATION_FOCUS`：这个题最有自己身份的具体东西是什么。它可以只是一个行为、关系、异常、证据、人物处境或终点；**不要求入口、场景、推进、证据、payoff 每一层都创新。**

只要用户明确要求“独具创意 / 高质量 / 最有上限 / 最强 / 冠军候选 / 顶档”，最强候选仍必须做 `HIGH_BAR_CHALLENGE`；高标准负责找真实弱点，不负责把简单答案加工复杂。

调查、探索、工作任务、回乡、旅行、寻找资料、失踪调查、近身威胁等成熟 story grammar 本身不是淘汰理由。真正危险的是整条观看体验可被现成模板替换，且没有一个具体 `INNOVATION_FOCUS`；或反过来为了证明原创不断叠第二机制、额外世界和身份反转。

有 benchmark 时，既允许它在 GUIDED 模式帮助当前弱点找成熟路径，也必须按 `creative-provenance.md` 隔离作品指纹。外部高水位比较仍和来源独立性分开。

## 2. 只保留三个一级筛选

按顺序判断：

1. **这个故事入口我愿不愿意进**：先使用已经冻结的 `ENTRY_PULL / ENTRY_DEBT / LATE_HOOK`。普通观众不用知道后续机制，就应当明白当前发生了什么，并拥有一个具体、未完成的继续理由。清楚但只让人觉得“作者设计了一个怪现象”不够；如果真正的欲望必须靠第二层解释才成立，先修入口。
2. **图片是不是核心**：最值钱的内容能否主要通过人物、空间、物件、证据、变化、尺度、行为或可见结果获得，而不是依赖长解释、内心、语音或议题讨论才成立。
3. **确认以后还想不想看**：假设观众已经看过 2–3 次足以证明核心异常 / 承诺的画面，后面是否仍有明确的**后续观看牵引**。它可以来自持续接近或进入、现实后果、人物选择、关系变化、威胁逼近、对象被重新理解、空间 / 尺度真正打开、具体真相、核心兑现，或自然出现新的观看问题。**不要求强制换问题，也不能只剩更多同类证据。物理距离本身不能单独充当故事距离。**

其他标准只能帮助诊断，不得压过这三项。

## 3. 做一次耐久、反模板与候选池检查

### 三次确认测试

假设核心异常已经被连续确认三次：

> **然后呢？继续看还能获得什么此前没有获得的观看价值？**

有效答案可以是更接近 / 真正进入、危险更近、异常造成现实后果、人物选择改变、空间打开、对象身份或性质被重新理解、具体真相出现、尺度改变对象性质，或前面的承诺真正发生到顶。

如果答案只是“再来一张更离谱的同类证据”“数量更多”“把同一东西拍得更完整”，序列耐久度是假象。更近 / 更大如果带来新的结构、用途、行为、关系、风险或世界尺度，仍然有效。

### 题目余量检查

问：

> **一句话题目是否已经把最终最值钱的对象 / 空间 / 结果基本说完？如果观众现在就看到一张足够清楚的确认图，后面还剩什么必须通过连续故事才能得到？**

如果剩下的主要只是走过去、进去、看更多细节、拍完整全景，降低优先级。一个题可以公开核心对象，但公开以后还要自然产生行为、后果、功能、人物选择、危险、关系变化、尺度重定义或题目尚未泄露的具体发现。这里不要求强制反转，也不要求再造第二个谜。

### 观看债务检查

对高潜种子额外问一句：

> **第一层结束以后，观众心里到底欠着哪一件未完成的事？**

它可以是某个人的命运、一个威胁会不会真正追上来、某个地方是否存在、某个行动会造成什么、某个异常明显要完成什么，或一次调查 / 寻找最终会抵达哪个具体事实。

“为什么这么怪”“这套规则怎么运作”可以制造好奇，但当它几乎是唯一债务时，顶档竞争力要谨慎。不要为了制造债务强行加生死、追逐或身份反转。

### Payoff Ceiling｜只证明上限，不锁结局

对最强候选内部写一个不传给 Production 的 `PAYOFF_CEILING`：

> **如果这个题做到最好，观众最终至少可能亲眼看到 / 确认什么具体对象、事件、事实、选择结果或可见变化？**

若只能写“真相浮现”“空间重叠”“时间失去一致性”“世界被重新定义”等方向词，去掉抽象词后再用一张图片和一句普通话说明具体发生了什么；讲不清时，说明回报上限仍然只是概念。

`PAYOFF_CEILING` 只用于证明题目值得等到后面，不等于正式结局，不锁 Story。

### 观看体验反模板

熟悉母型允许使用。判断重点放在整条观看体验：

- 入口是否熟悉；
- 核心异常是否熟悉；
- 后续靠什么往前是否熟悉；
- 最值得等到最后的东西是否也熟悉。

只有其中一两项常见不构成失败。若四层大多都能被现成模板替换，且没有一个具体、不可替代的观看价值，再淘汰。

### 题眼唯一性

问：

> **这个题有没有一层具体观看价值，换成别的名词就会明显失去它？**

独特性不要求拥有“从未有人设计过的世界机制”。可以是一个非常具体的怪事、地点、威胁、行为、人物处境、世界尺度或终点。

### 创意来源独立性检查

对最终候选和重点强种子按 `references/creative-provenance.md` 做 `COMPOSITE_LEAKAGE_AUDIT`。可以拆看入口债务、人物关系、场景、异常载体、证据方式、推进和 payoff，但**不按相似槽位数量机械判定**。重点判断 `SPECIFICITY + COMBINATION + SALIENCE`：相似的是通用 story grammar，还是足以让人认出某篇作品的具体指纹组合。

如果候选最有辨识度的价值主要来自一个 / 多个已暴露 benchmark 的高识别组件重新拼装，标记 `PROVENANCE_STATUS = REVIEW / LEAK`；成熟的“失踪案被新证据重启”“一路进入未知”“同一威胁持续逼近”等 spine 本身不构成泄漏。

强入口、高 Payoff 或高 `TOP_TIER_CONTENDER` 不能替来源问题洗分；来源审查也不能因为使用成熟故事语法就强迫候选再发明一套新机制。

### 候选池故事发动机去重

最终池提交前，把专名暂时删掉，只看三个问题：

1. 异常主要怎么工作；
2. 人物 / 事件为什么继续；
3. 后面主要靠什么产生新价值。

如果多个最终候选明显共享同一故事发动机，例如都能压成“两个对象建立对应 → 人操作一边 → 另一边反馈 → 关系扩大”，说明用户实际拿到的是一组换皮选择。**重做其中一部分即可，不设机械配额，也不封杀某一种合法机制。**

### 候选池入口发动机去重

在故事发动机去重之前，按 `references/entry-design.md` 做一次 `POOL_ENTRY_ENGINE_AUDIT`：删掉专名，只看“观众为什么现在需要下一步”。如果多数候选都依赖“无生命对象 / 环境突然违反物理规律”来开门，即使后续故事发动机不同，也标记 `POOL_ENTRY_RISK` 并重做一部分入口。熟悉的返乡、失踪、工作、寻找、近身威胁、动物目的行为都可以合法占位，不设机械比例。

## 4. 不把“行动”误当成高级，也不把“更近 / 更大”误判成低级

持续价值可以来自：

- 人物实际行动与结果；
- 异常主动逼近或持续发生；
- 新证据带来的新判断；
- 同一对象的身份 / 性质被重新理解；
- 空间、距离、尺度或位置关系改变；
- 已经看过的画面后来获得新含义；
- 一个不可能世界被真正确认；
- 一个现实问题终于抵达具体结果。

观察、调查、等待、跟随、被迫经历都可以成立。只有它们反复提供同一种价值时才算停滞。

距离更近、规模更大也不是天然弱升级：如果只是把同一事实放大，就是重复；如果新的距离让原先看不见的结构、关系、用途、行为、危险成立，或尺度变化重新定义对象、打开新世界、兑现核心奇观，它就是新的观看价值。

## 5. 图片原生性

在候选提交前问一次：

> **把大部分字幕和解释拿掉，这个题最想看的东西还在不在？**

如果核心快感主要依赖长语音、多条规则、人物内心、制度辩论或文字谜底，优先重构题，而不是假设 Production 能靠更多分镜补救。

## 6. Topic 不写正式故事，但允许内部证明“这颗种子会长”

Topic 阶段默认不输出、不锁定：

- 正式事件顺序和结局；
- 完整规则体系；
- 人物弧和主题升华；
- 伏笔回收网络；
- 正式图数；
- 摄影者 / 影像来源；
- 第一 / 第三视角或具体观察位置；
- 分镜与 Prompt。

第 1 节的三步事件试跑只是内部压力测试，不能作为半成品剧本传给 Production，也不能因为一次试跑成立就把该顺序视为锁定剧情。

参与、职业能力、互动、进入 / 使用 / 失败 / 协作、关系升级等都只是条件工具。题材天然需要时才使用，不作为强题必备项。

## 7. 标题和一句话题眼分开

**标题负责把观众带进来；一句话题眼负责把选题说清楚。** 两者不能再合并成同一个字段。

提交最终候选前读取 `references/title-design.md`。标题停在 **`FIRST_SUFFICIENT_DEBT_POINT`：观众第一次已经拥有足够理由继续的最早位置**。这个位置可以早于第一件异常、正好落在第一件异常，也可以到第一次确认；不要把“必须交代第一异常”写成固定标题公式。深层机制、第一次大 reveal、最终对象或正式结局仍然通常后置。

允许按题材自然选择三类入口，不设配额：

- **故事开门型**：人物 / 现实处境 + 当前未完成的事情；异常可以已经出现，也可以暂时不出现；可以像故事第一句话一样稍长；
- **事件事实型**：直接给一个清楚、具体、正在发生的事件；这个事件单独拿出来就应形成观看债务，不能只是一条精确的异常参数；
- **事件命名型**：一个硬锚点（地点 / 对象 / 编号等）+ 一个事件或状态，适合档案感、调查感、大世界题。

留白必须建立在具体事实之上。不要写成“那天发生了怪事”“我永远忘不了那一晚”这类空悬念，也不要只剩“拟合、沉浸、入梦”一类没有硬锚点的概念名。

如果核心对象公开以后仍会持续逼近、行动、造成后果或打开世界，标题可以直接说出它；标题设计不要求刻意藏谜底，也不要求每个标题都第一人称。

## 8. 输出真正有差异的候选

用户未指定数量时，默认给 6 个最终候选。输出前允许内部重做多轮，但只给用户最终池。

当用户明确要求“独具创意 / 高质量 / 最有上限 / 最强 / 冠军候选 / 顶档”时，先从最终池挑最强的 1–3 个，按 `references/top-tier-development.md` 做 **`HIGH_BAR_CHALLENGE`**，内部记录 `HIGH_BAR_CONTENDER = YES / BORDERLINE / NO`。这个质量门不依赖 benchmark。

如果同时存在 benchmark，再在高标准内部判断之后做 **`EXTERNAL_TOP_TIER_COMPARISON`**，内部记录 `TOP_TIER_CONTENDER = YES / BORDERLINE / NO`。外部比较可以让候选降级、重排或继续深挖，但不得因为某篇对标很强就把候选改成它的题材 / 场景 / 反转换皮。若任务明确要求原创 / 独具创意，还要独立通过 `PROVENANCE_STATUS` 检查；顶档竞争力与来源独立性分开。

不要要求 6 个全部达到最高档。最终池可以同时包含冠军候选、稳定方向和少量冒险方向；但当用户明确要高质量，而最强候选的 `HIGH_BAR_CONTENDER` 仍全部是 `NO`，回到高潜种子继续深挖，不要把一池均匀的“都还不错”当成完成。若用户还明确要求正面对标最高档，则外部 `TOP_TIER_CONTENDER` 也至少应出现一个可信的 `YES` 或明确说明为什么仍只有 `BORDERLINE`，不能把内部自评替代外部比较。

第一遍内部判断分两次：

1. **先只看标题**：没人解释时，我会不会因为一个具体事实产生观看债务；
2. **再看一句话题眼**：这个选题本身是否清楚、有生命。

标题弱不能靠一句话题眼替它加分；标题很强也不能替一个空选题过关。

每个候选保持短，只写：

- **标题**：面向观众的进入标题；不等同于一句话题眼；
- **一句话题眼**：用一句话把人物 / 处境 / 第一层异常或核心选题说清，允许比标题多交代一层，但仍不提前写完整机制和正式结局；
- **这题到底好看在哪**：用一句普通话说清最值得看的具体东西，不用分析术语替题辩护；
- **最先想亲眼看到什么**：第一层观看承诺；
- **核心成立后为什么还能继续看**：写后续观看牵引，优先说明事情会怎样继续获得新价值；若主要只能写“继续理解这套机制”，标记风险；
- **最值钱的视觉内容**；
- **核心兑现潜力**：写这个题最值得抵达的方向或层级，优先能落成具体对象、事件、变化、行动结果或事实确认；只写潜力，不提前锁正式结局；
- **最大陈旧 / 失速风险**。

不要把候选写成“前三张 / 中段 / 结尾”的剧情提纲，也不要用长篇分析替候选辩护。

最终池再做一次**标题句式去重**，同时检查 `PITCH_TITLE` 与数字功能：如果大多数标题虽然句法不同，却都能压成“时间 / 职业包装 + 一个不可能物理现象”，同样属于入口包装聚类。精确数字只有在承担现实背景、证据可信度或故事意义时加分；若只是让异常显得精确新奇，不自动加分。

如果最终池整体平庸、故事发动机明显聚类，**不要硬选冠军**；内部重做其中有问题的选题。若只是标题平、泄题或句式聚类，优先只修标题，保护已经成立的题眼与故事发动机。

## 9. 选中后锁定题目核心

用户选中后锁定：

- **标题**：面向观众的进入标题；
- 一句话核心题目；
- 主角 / 进入这件事的最低必要背景；
- 核心异常或主要问题；
- **创新锚点 / INNOVATION_ANCHOR**：这个题最需要 Production 保住的具体观看身份；可以是行为、关系、异常、证据、处境或终点，不要求是新物理机制；
- 核心观看欲望；
- 最值钱的视觉内容；
- **后续观看牵引**；
- 核心兑现潜力。

`后续观看牵引` 继续兼容旧字段 `下一层观看问题`，把旧字段视为牵引的一种形式，不要求为了升级格式重写已锁题目。

生成 Handoff 时可以补 2–4 个**无顺序的视觉展开机会**，以及题材最自然的后劲方向；这些只是给 Production 的创作空间，不提前锁分镜或结局。

如果选中后才发现一个会明显破坏 Production 的硬缺陷，先尝试在原题内修正表达；原题内确实解决不了时，明确提出**最小题目变更**并等用户确认，不自动替换。

按照 `references/handoff-spec.md` 输出。

## 10. 来源边界

如果题来自历史、民俗、宗教、新闻、真实人物或现代受保护作品，读取 `references/source-boundary.md`，区分事实、传统、机制参考与新增虚构。若当前项目已经暴露具体现代作品，即使本轮用户没有再次点名，也读取 `references/creative-provenance.md`：隔离作品指纹；若用户明确要求参考对标，则成熟 story grammar 仍可按 `benchmark-isolation.md` 合法学习。

## 11. 最后一次内部检查

提交前只检查这些核心问题，不展示自审过程：

1. Blind Entry Gate 是否在看不到后续潜力时仍给出可信 `ENTRY_PULL / ENTRY_DEBT / LATE_HOOK`；
2. 三步试跑是否自然获得新的观看价值，而不是同一机制反复演示；
3. 核心异常确认以后是否仍值得看，不强制换问题 / 换机制；
4. 最值钱的东西是否主要能被图片承载；
5. 题目是否提前把最终最值钱的画面说透；
6. 是否存在清楚的 `INNOVATION_FOCUS`，同时避免要求每一层都创新；
7. 强种子的 `BASELINE_ALREADY_STRONG` 是否先被判断；baseline 已强时有没有被“再想一个更意外的”强行复杂化；
8. 真有弱点时，是否先执行 `PRESERVE → REPAIR → RECONSIDER`，而不是一上来推翻入口 / 人物 / 核心异常；局部修复无效时才 `REBUILD`；
9. 熟悉母型是否真的造成整条观看体验陈旧；不要因为熟悉就降级，也不要因为“安全”就放过平庸；
10. 候选池是否过度共享入口 / 故事发动机；去重只重做有问题的一部分，不把每个题强行做成完全不同物种；
11. 标题是否停在 `FIRST_SUFFICIENT_DEBT_POINT`，且没有句式 / pitch 聚类；
12. Story Debt 与 `PAYOFF_CEILING` 是否具体，且没有靠更大世界 / 更复杂机制虚抬上限；
13. `PROMPT PROVENANCE LOCK` 是否挡住模型自行补入的创意方向；
14. 当前上下文中的 benchmark 是否被正确拆成 `TRANSFERABLE_STORY_GRAMMAR` 与 `SIGNATURE_QUARANTINED`，没有把成熟 story spine 错当污染，也没有把作品指纹当自由素材；
15. `COMPOSITE_LEAKAGE_AUDIT` 是否按具体度、组合和显著性判断，而不是机械数相似槽位；
16. 若用户要求 benchmark-guided，是否先筛对标学习价值：高 craft 学 craft，高 novelty 但低 craft 只当灵感，低价值样本不因数据高就模仿；
17. benchmark 是否真正帮助选路径 / 修弱层，而没有让候选池大面积滑向对标的具体地点、人物、标志物、怪物、反转链与结局；
18. 若用户明确要求最高档，是否仍独立做 `TOP_TIER_CONTENDER`；顶档竞争力不能覆盖 provenance；
19. 有没有为了“丰富 / 聪明 / 独具创意”添加第二主机制、隐藏世界、身份反转或抽象终局，反而损害原本已经成立的故事欲望；
20. 有没有因为本轮强调成熟结构而过度保守：真正新鲜、但同时更好看、更清楚、更能兑现的高概念方案仍应被允许胜出。
