# 标题设计｜停在第一次“已经足够想继续”的位置

这份文件只解决 Topic 阶段的标题。标题负责让观众进门；一句话题眼负责把选题说明白。标题不能替一个弱入口制造不存在的欲望，也不能把好题提前讲完。

## 1. FIRST_SUFFICIENT_DEBT_POINT｜标题停在哪里

标题默认停在：

> **观众第一次已经拥有足够理由继续的最早位置。**

这个位置可能：

- 早于第一件超自然异常：失踪、寻找、返乡、邮件、关系、任务已经足够；
- 正好落在第一件异常：异常本身有明确威胁、目的或存在性问题；
- 到第一次确认：第一件异常过轻，确认后才形成可靠观看债务。

不要把“标题必须交代第一异常”写成固定公式，也不要为了神秘把真正有效的进入事实藏掉。

标题不负责证明整个脑洞有多聪明。深层机制、第一次昂贵 reveal、世界最终是什么、正式结局通常留给故事。

## 2. 三种自然标题入口

按题材选最顺的一种，不设比例。

### A. 故事开门型

人物 / 现实处境 + 当前未完成的事情。异常可以已经出现，也可以暂时没有出现。可以像有人开始讲一件亲历的事。

适合：返乡、失踪、调查、寻找、工作遭遇、家庭关系、民间异闻、第一人称伪纪实。

### B. 事件事实型

直接给一件清楚、具体、正在发生的事件。这个事件单独拿出来就应制造观看债务；若只是“一个对象违反了物理规律”，但观众还不知道为什么值得关心，先回 Topic 修入口。

适合：异常行为、威胁逼近、设施失控、自然现象反常、主动存在。

### C. 事件命名型

硬锚点 + 事件 / 状态。硬锚点可以是地点、对象、编号、案件名等。

适合：档案感、调查感、大世界、系列世界观。短标题可以有意味，但不能只剩抽象词。

## 3. 控制揭示深度

标题写完后问：

> **为了让观众已经足够想继续，我最少需要交代到哪一层？**

高风险写法常把三层压在一句里：

`异常是什么 + 它怎么运作 + 最后会造成什么`

优先保留足够制造债务的最早事实，同时留下昂贵 reveal。

如果公开核心对象后，真正的故事仍来自它持续逼近、行动、造成后果、带来选择或打开世界，可以直接说出对象；不要为了藏而藏。

## 4. PITCH_TITLE CHECK｜像故事开门，还是像设定汇报

问：

> **这句话像有人开始讲一件事，还是像创作者向我汇报“我的核心设定是……”？**

常见 pitch 感来源：

- 时间 / 职业包装 + 精准异常参数；
- 一句话把对象、异常方式和升级方向压满；
- 标题的主要价值是证明脑洞“很具体、很新奇”，没有自然的未完成事件。

Pitch 感不是自动失败。档案题、事件事实题可以很硬；但整池标题都像设定提案时要重做入口包装。

## 5. NUMBER FUNCTION CHECK｜数字为什么在这里

不要禁止数字。只看它承担什么功能。

优先保留：

- 年龄、年份、失踪时长、次数等现实背景；
- 关键证据需要的距离 / 数量；
- 会直接改变故事意义的数字。

谨慎使用：

- 只为让异常显得更精确、更“AI 脑洞”的参数；
- 换成别的数字也不改变观看债务的数字。

数字不自动增加真实感，也不自动增加标题竞争力。

## 6. 具体比模糊重要

留白仍要建立在具体事实之上。优先出现至少一个能想象的现实锚点：人、关系、地点、物件、行为、任务、损失、时间变化或异常结果。

避免：

- `那天开始，一切都不对劲`
- `我永远忘不了那个夜晚`
- 只有抽象概念、没有硬锚点的文学名

## 7. TITLE_ONLY_REPAIR 与 ENTRY_AND_TITLE_REPAIR

先问底层入口是否已经成立：

- **TITLE_ONLY_REPAIR**：入口本身有强债务，只是标题泄题、太虚、太长、句法差或包装错；只修标题。
- **ENTRY_AND_TITLE_REPAIR**：标题不好，底层第一层事件本身也弱，真正欲望要靠后续解释才出现；先回 Topic 修入口，再重新写标题。

不要用文案技巧替弱入口化妆。

## 8. 候选池标题检查

把所有标题单独排在一起：

1. 检查句法是否聚类；
2. 检查是否大多共享“宣布一个不可能物理现象”的进入发动机；
3. 检查精准数字是否大量承担机制参数而非现实故事功能；
4. 检查是否都停在同一揭示层。

若只是句式问题，修标题；若底层入口发动机也聚类，回 `entry-design.md` 的 `POOL_ENTRY_ENGINE_AUDIT` 重做一部分种子。

## 9. 最后五问

提交标题前只问：

1. 它是否停在 `FIRST_SUFFICIENT_DEBT_POINT`？
2. 没有一句话题眼替它解释时，我为什么现在想继续？
3. 它有没有把第一次昂贵 reveal、深层机制或结局提前说掉？
4. 它是否像故事开门，而不是一条“核心设定 pitch”？
5. 如果标题不好，问题到底只在文案，还是底层入口也需要修？
