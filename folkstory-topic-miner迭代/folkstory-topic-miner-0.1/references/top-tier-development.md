# High-bar Development｜先保强项，再决定要不要深挖

这份文件只在已经出现高潜种子，或用户明确要求高质量 / 独具创意 / 最有上限 / 冠军候选时读取。

目标：**先确认 baseline 是否已经够强；只有存在明确弱点时才继续创新。** 不把每个好点子继续加工成高概念。

有 benchmark 时按 `benchmark-isolation.md`：用户要求参考时，可以学习可迁移 story grammar；作品指纹仍按 `creative-provenance.md` 隔离。

## 1. 先选少数强种子

第一轮粗种子先通过 Blind Entry Gate 与三步事件试跑，只挑 2–4 个最有希望的继续。

优先看：

- `ENTRY_PULL` 至少 MEDIUM，高标准优先 STRONG；
- `ENTRY_DEBT` 不靠后续解释也成立；
- 图片承载强；
- 三步试跑能自然往前，不立刻变规则演示；
- 有一个具体、可记住的 `INNOVATION_FOCUS` 或观看身份。

不要因为用户说“独具创意”就默认所有候选必须复杂。

## 2. BASELINE FIRST｜先写最自然的第一条后续

对每个强种子先写 `BASELINE`：如果完全不追求聪明，这个题最自然、最好懂、最有故事惯性的下一条路线是什么？

随后先判断：

`BASELINE_ALREADY_STRONG = YES / NO`

`YES` 至少满足：

- 第一层已经想看；
- 人物 / 事件为什么继续自然；
- 后续不是纯重复证明；
- 有具体 Story Debt；
- 能走向具体 payoff；
- 理解成本低；
- 熟悉结构没有把题眼本身磨平。

如果 `YES`，**允许直接停止第二层发散**。第一联想不会因为“是第一联想”就自动降级。

如果 `NO`，先写清唯一主要弱点，例如：

- 第二层过于可预测；
- 中段只能重复机制；
- payoff 太轻；
- 原始异常没有真正影响人物；
- 题眼换个名词就一样；
- 必须再外挂一套机制才能走下去。

没有明确弱点，不进入继续发散。

## 3. PRESERVE → REPAIR → RECONSIDER → REBUILD

深挖严格遵循这个顺序。

### PRESERVE

先冻结当前已经成立的部分：入口债务、人物动机、核心行为 / 异常、最值钱视觉、简单有效的推进。不要因为修第二层把第一层也换掉。

### REPAIR

只针对诊断出的弱层寻找少量替代：下一件具体事件、第二层含义、人物选择、后果或 payoff 方向。

优先问：

- 哪件事会真正改变处境，而不是只让世界更大；
- 能不能让原有核心产生后果，而不是再发明一套核心；
- 能不能保持同一威胁 / 调查 / 探索继续推进；
- benchmark 若有合适的成熟 grammar，能不能只借它解决当前弱点。

### RECONSIDER

修完以后重新评估整题。已经达到高标准就停，不为了“还能更意外”继续加工。

### REBUILD

只有局部修复仍无法解决结构问题时才重构，例如：入口本身不想看、核心异常天然没有后续、图片承载不足、payoff 无法落地。重构也优先保留仍有价值的局部，不做全盘清零。

## 4. INNOVATION_FOCUS｜创新集中在真正值钱的位置

内部写一句：

`INNOVATION_FOCUS = 这个题最有自己身份的具体东西是什么？`

可以是：

- 一个具体行为；
- 一种人物关系；
- 一个异常对象 / 证据；
- 一种情绪重分类；
- 一个终点；
- 一个视觉关系。

只要这一层足够具体、不可随便换名词替代，其他层可以使用成熟 story grammar。

不要要求入口、人物、场景、异常、推进、证据、payoff 七层都“没见过”。

## 5. 第一联想风险检查改成“有问题才触发”

只有以下情况继续找第二层：

- 第一层很锋利，第二层明显过早可猜；
- 第二层只是最直觉的功能解释，且让故事迅速失速；
- 中段只能继续证明同一规则；
- payoff ceiling 明显低于入口承诺；
- 与某 benchmark 的高度具体签名组合过近，需要局部换掉受污染层。

如果 baseline 是“同一威胁持续逼近”“单线调查越来越接近真相”“一路探索到核心空间”且每一段都有真实观看价值，不必拧出第二套世界观。

## 6. 扩世界偏置与过度创新检查

出现以下任一倾向时先停：

- 为了升级突然增加隐藏世界、幕后组织、实验室、第二套怪物；
- 为了“更原创”强加身份反转、时间循环、空间映射；
- 原本简单的人物动机被抽象机制替代；
- 每段都需要观众学习一个新规则；
- 最后只能靠“现实被重构 / 人被同化 / 世界被重新定义”这类抽象词描述。

问：

> **保留现有核心，不增加新的主机制，下一件什么具体事情仍能让故事升级？**

答得出来，优先走这条。

## 7. STORY_DEBT + PAYOFF_CEILING

对高潜候选内部继续保留：

`STORY_DEBT = 第一层结束以后，观众到底欠着哪一件未完成的事？`

`PAYOFF_CEILING = 如果做到最好，观众最终至少可能亲眼看到 / 确认什么具体对象、事件、事实、选择结果或可见变化？`

二者都不要求复杂，也不锁正式剧情。

## 8. HIGH_BAR_CHALLENGE

用户明确要高质量时，对最强 1–3 个候选检查：

1. Entry pull；
2. Story debt；
3. Baseline 是否已经强，若弱是否只修了弱层；
4. 中段有没有 story inertia；
5. Payoff ceiling 是否具体；
6. `INNOVATION_FOCUS` 是否足以给作品自己的身份；
7. Comprehension cost 是否可控；
8. 有没有为了冲顶添加无必要的新机制。

记录：`HIGH_BAR_CONTENDER = YES / BORDERLINE / NO`。

`YES` 可以是非常熟悉的母型，只要具体观看身份、推进和兑现够强。

## 9. EXTERNAL_TOP_TIER_COMPARISON

有 benchmark 且用户要求最高档比较时，再检查：

- 入口与 Story Debt 是否同档；
- baseline 的故事惯性是否比对标更弱；
- 中段是否更容易停在机制演示；
- payoff 是否更轻；
- 是否为了显得原创付出了更高理解成本；
- 是否存在一个本来已经强的简单路线，却被额外创新拖差。

如果外部比较暴露弱点，回到 `PRESERVE → REPAIR`。不要直接嫁接高水位作品的具体地点、人物、异常、标志物或反转链。

## 10. 停止规则

当一个种子已经：

- 入口强；
- 故事会自然继续；
- 有自己的具体身份；
- 中段不空；
- payoff 有上限；
- 理解成本合理；

就停止继续创新。

> **高标准的目的，是把弱点修掉，不是把简单答案加工到认不出来。**
