# Creative Provenance｜保护作品指纹，不封锁成熟故事语法

这份文件解决两个不同问题：

1. 模型有没有把自己补出的题材方向冒充成用户要求；
2. 新题有没有过度依赖已暴露 benchmark 的**高度辨识性作品指纹**。

它不负责禁止成熟母题，也不把通用 story spine 视为某篇作品的私有资产。

## 1. PROMPT PROVENANCE LOCK｜先锁定谁真的提出了什么

发散前内部区分：

- `USER_EXPLICIT`：用户真实提出的题材、风格、对象、禁区、数量、媒介、质量目标；
- `TASK_REQUIRED`：执行 Skill 需要的中性流程默认；
- `ASSISTANT_INVENTED`：模型为了演示、方便创作或“更真实”自行添加的创意方向。

模型不能把 `ASSISTANT_INVENTED` 反写成用户偏好。用户已经给出实质请求时，即使要求“make up a realistic user prompt”，也只补中性流程信息，不擅自加乡村、返乡、失踪、祖屋、葬礼、深海、探险等会改变创意分布的条件。

如果用户真的只要求随机演示，可以自行选情境，但内部标记 `ASSISTANT_INVENTED_DEMO`，不能用该次结果证明无约束原创分布。

## 2. CONTEXT SPLIT｜把“成熟语法”和“作品指纹”分开

当前对话、项目、Library 或历史测试里已经读过具体作品时，不再把所有内容一刀切隔离。

### `TRANSFERABLE_STORY_GRAMMAR`｜允许学习

包括：

- 入口功能与观看债务；
- 通用 story spine 与推进发动方式；
- 人物为什么继续；
- 事件惯性、节奏、信息揭示；
- payoff function；
- 熟悉母型怎样保持有效；
- 图片承担证据、距离、尺度、结果或身份确认的方式。

用户明确要求参考 benchmark 时，这些内容可以按 `benchmark-isolation.md` 参与创作。

### `SIGNATURE_QUARANTINED`｜继续隔离

包括：

- 原人物 / 角色组合的具体实现；
- 原地点生态与进入路径的具体组合；
- 标志性物件、怪物、生物、场面；
- 独特异常机制的具体实现；
- 高辨识证据方式；
- 可逐段映射的推进 / 反转链；
- 原结局 / 终局画面；
- 某篇作品独有标题结构、台词和表达。

目标是：**隔离作品指纹，不隔离“失踪调查怎么启动”“威胁怎样持续逼近”这种成熟故事语法。**

## 3. DEMO PROMPT DRIFT CHECK｜演示 Prompt 不能先替用户选题材

虚构示例 Prompt 后做内部差分：

> 删掉用户原话以后，我新增的要求有没有改变“会想到什么题”？

- 中性执行约束：可以保留；
- 创意方向约束：删除，除非用户明确让模型随机指定题材。

特别警惕为了“真实”一次性加入返乡、失踪、祖屋、葬礼、务工、分家等可直接提供故事零件的列表。

## 4. COMPOSITE LEAKAGE AUDIT｜看辨识性组合，不机械数槽位

对最终强候选可拆成：

1. `ENTRY_DEBT`
2. `RELATION`
3. `SETTING`
4. `ANOMALY_CARRIER`
5. `EVIDENCE_METHOD`
6. `PROGRESSION`
7. `PAYOFF_FAMILY`

拆槽只是为了看清来源，不代表“相似三个槽位就失败”。真正判断三项：

- **SPECIFICITY**：相似的是通用语法还是具体独特实现；
- **COMBINATION**：这些具体元素组合起来是否可指向同一作品 / 几篇刚读的作品；
- **SALIENCE**：相似部分是否承担新题最有辨识度、最值钱的内容。

风险信号：

- 高度具体的人物关系 + 场景 + 标志物 / 异常 + 推进连续重合；
- 把几篇高水位作品最醒目的具体组件拼成一个新题，而新增部分只剩职业 / 年代 / 地名；
- 从入口到 payoff 能逐段映射一篇作品，只换名词；
- 新题的 `INNOVATION_FOCUS` 实际就是某个已暴露作品的签名设计。

不构成泄漏的常见情况：

- 都使用失踪、返乡、调查、探索、封闭空间、近身威胁；
- 都采用“旧事件被新证据重启”“一路进入未知”“同一威胁越来越近”等通用 spine；
- 都以具体 payoff 结束，但对象、事件和价值完全不同。

内部记录：`PROVENANCE_STATUS = CLEAN / REVIEW / LEAK`。

## 5. COUNTERFACTUAL INDEPENDENCE｜拿掉指纹后，自己的核心还在不在

对疑似候选问：

> 如果把已知 benchmark 的专名、标志物、独特场面、具体机制和原结局全部拿走，这个题是否仍有一个清楚、具体、属于自己的 `INNOVATION_FOCUS`，并能沿成熟故事语法自然长下去？

- 仍然成立：可以保留；
- 只剩空泛母题，而最抓人的具体价值全部来自对标：重做受污染部分；
- 使用通用 spine 本身不会导致失败。

## 6. 不要过度纠偏

- 成熟母题不是禁词；
- 熟悉 story spine 可以直接使用；
- 用户点名的题材当然合法；
- 一个题只需要在真正重要的位置拥有自己的具体身份，不要求七个槽位全部新；
- provenance 不奖励复杂度，也不要求“为了证明原创再叠一套机制”。

最终目标：

> **作品整体有自己的身份，同时允许 AI 借用人类已经验证有效的故事常识。**
